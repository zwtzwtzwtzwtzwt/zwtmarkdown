在操作链表时，指针的来回赋值确实很容易让人“绕晕”，最常见的错误就是导致**链表断裂**或**死循环**。为了确保万无一失，插入节点时需要重点关注以下几个核心注意事项：

### 1. 核心准则：“先连后断” (操作顺序至关重要)

这是单链表插入最重要的一条规则。当你试图在节点 A 和节点 B 之间插入新节点 N 时，**必须先将 N 连接到 B，然后再断开 A 并将 A 连接到 N。**

- ✅ **正确顺序：**
    
    1. `N.next = A.next` （让新节点 N 指向节点 B）
        
    2. `A.next = N` （让节点 A 指向新节点 N）
        
- ❌ **致命错误顺序：**
    
    如果先执行 `A.next = N`，此时 A 原来指向 B 的指针就丢失了（链表断裂），你将永远无法找到 B 节点，导致后续数据全部丢失。
    

### 2. 警惕三大“边界条件” (Edge Cases)

在编写插入逻辑时，仅仅考虑“在中间插入”是不够的，必须通过代码测试以下三种极端情况：

- **向空链表插入：** 此时链表的头指针（Head）为空。插入后，新节点既是头节点，也是尾节点。
    
- **在头部插入（头插法）：** 新节点需要变成新的头节点。记得更新全局的 Head 指针，使其指向新节点（例如：`new_node.next = head; head = new_node;`）。
    
- **在尾部插入（尾插法）：** 新节点的 `next` 必须明确指向 `null`（或 `nullptr` / `None`），并更新原有尾节点的 `next` 指向新节点。如果维护了 Tail 指针，也需要同步更新。
    

### 3. 双向链表的额外负担（四步操作）

如果是双向链表（Doubly Linked List），除了处理 `next` 指针，还要处理 `prev`（前驱）指针。在节点 A 和 B 之间插入 N 需要四次指针变换，同样遵循“先处理新节点的指针，再修改老节点的指针”原则：

Plaintext

```
1. N.prev = A       // 新节点指向前驱
2. N.next = A.next  // 新节点指向后继 (B)
3. A.next.prev = N  // 后继节点 (B) 的 prev 指向新节点 (注意检查 B 是否为空)
4. A.next = N       // 前驱节点 (A) 的 next 指向新节点
```

### 4. 越界与空指针检查

- **位置越界：** 如果按索引位置插入（例如“在第 10 个位置插入”），但在遍历寻找插入点时，链表总共只有 5 个节点。代码需要能优雅地处理这种情况（例如返回错误、抛出异常或直接插在尾部），而不是抛出 `NullPointerException` 或发生段错误。
    
- **节点有效性：** 确保传入的“插入位置节点”和“新节点”都不是空指针。
    

### 5. 内存分配与泄漏（针对 C/C++ 等语言）

- 在使用 `malloc` 或 `new` 为新节点分配内存后，务必检查**内存是否分配成功**。如果内存耗尽导致分配失败，直接操作空指针会导致程序崩溃。
    
- 如果在插入操作的逻辑中发生异常并提前 `return`，要确保已经分配但未成功接入链表的新节点内存被正确释放（`free` 或 `delete`），以防止内存泄漏。
