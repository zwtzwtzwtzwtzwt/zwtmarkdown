### 核心本质区别

一句话总结：**单行函数是「逐行计算，每行一个结果」，聚合函数是「批量汇总，一组一个结果」**。

- 单行函数：输入是一行的字段值，输出也是对应这一行的一个计算值，有多少行输入就有多少行输出；
- 聚合函数：输入是一组（多行）的字段值，输出是这一组汇总后的一个值，有多少组就有多少行输出。

---

### 一、单行函数详解

单行函数（Scalar Function）针对每一行数据独立计算，不改变结果的行数，只对每行的字段做加工、转换、计算。

#### 常见分类 & 示例（基于学生/成绩表）

|函数类型|代表函数|示例 SQL|效果说明|
|---|---|---|---|
|字符串函数| `CONCAT` / `SUBSTRING` / `LENGTH` / `TRIM` | `SELECT sname, CONCAT('学号:', sid) AS 学号标签 FROM student;` |给每个学生的姓名拼接学号前缀，每行对应一个结果|
|数值函数| `ROUND` / `ABS` / `CEIL` / `FLOOR` | `SELECT sid, score, ROUND(score, 0) AS 取整分数 FROM sc;` |对每行成绩四舍五入取整，行数和原成绩表完全一致|
|日期函数| `YEAR` / `DATE_ADD` / `DATEDIFF` | `SELECT sid, YEAR(birthday) AS 出生年份 FROM student;` |从每行的生日字段提取年份，逐行计算|
|流程控制函数| `IF` / `CASE WHEN` / `IFNULL` | `SELECT sid, score, CASE WHEN score>=60 THEN '及格' ELSE '不及格' END AS 等级 FROM sc;` |每行根据分数判断等级，逐行输出|

#### 核心特点

1. 计算不跨行，每行独立运算，互不影响；
2. 输入行数 = 输出行数，不会压缩数据；
3. 几乎可以写在 SQL 的所有位置（WHERE、SELECT、GROUP BY、HAVING、ORDER BY）。

---

### 二、聚合函数详解

聚合函数（Aggregate Function）针对**一组多行数据**做汇总统计，最终只返回一个汇总值，会压缩数据行数。

#### 常见分类 & 示例（基于学生/成绩表）

|函数|作用|示例 SQL|效果说明|
|---|---|---|---|
| `COUNT(*)` / `COUNT(字段)` |统计行数/非空值数量| `SELECT cid, COUNT(*) AS 选课人数 FROM sc GROUP BY cid;` |每门课程为一组，统计每组的学生人数，有多少门课就返回多少行|
| `SUM(字段)` |求和| `SELECT sid, SUM(score) AS 总成绩 FROM sc GROUP BY sid;` |每个学生为一组，计算该生所有课程的总分|
| `AVG(字段)` |求平均值| `SELECT cid, AVG(score) AS 平均分 FROM sc GROUP BY cid;` |每门课程为一组，计算该课程的平均成绩|
| `MAX(字段)` / `MIN(字段)` |求最大/最小值| `SELECT MAX(score) AS 最高分 FROM sc WHERE cid='001';` |整张表（一个组）返回 001 课程的最高分，仅 1 行结果|
| `GROUP_CONCAT(字段)` |字符串拼接汇总| `SELECT cid, GROUP_CONCAT(sid) AS 学生学号列表 FROM sc GROUP BY cid;` |每门课的所有学号拼接成一个字符串返回|

#### 核心特点

1. 跨多行计算，对整组数据做汇总；
2. 输入行数远大于输出行数，数据被压缩；
3. 不分组时，整张表默认为一个组，仅返回 1 行结果；分组后，每组返回 1 行结果。

---

### 三、完整对比表

|对比维度|单行函数|聚合函数|
|---|---|---|
|**作用粒度**|逐行计算，每行独立运算|分组计算，整组汇总运算|
|**返回行数**|输入行数 = 输出行数，不压缩|输入行数 >> 输出行数，按组压缩|
|**核心作用**|字段值的转换、加工、格式化|数据的统计、汇总、计算整体指标|
|**可书写位置**|WHERE、SELECT、GROUP BY、HAVING、ORDER BY 全位置可用|只能写在 SELECT、HAVING、ORDER BY 中|
|**执行时机**|WHERE 行过滤、SELECT 字段投影等阶段都可执行|GROUP BY 分组之后才执行，WHERE 阶段无法使用|
|**是否依赖分组**|完全不需要分组|可分组使用，也可全表作为一组使用|
|**NULL 处理**|输入为 NULL 则输出为 NULL，逐行处理|自动忽略 NULL 值，只统计非空行|

---

### 四、最关键的使用规则（高频考点）

#### 1. 聚合函数绝对不能写在 WHERE 中

这是 SQL 最经典的语法规则，根源是**执行顺序**： `FROM → JOIN → WHERE → GROUP BY → 聚合函数计算 → HAVING → SELECT → ORDER BY`

WHERE 执行的时候，还没有进行分组，聚合函数还没开始计算，因此 WHERE 里写聚合函数会直接报错。

```
-- 错误写法：WHERE 中使用聚合函数
SELECT sid FROM sc WHERE AVG(score) > 60;

-- 正确写法：分组后过滤用 HAVING
SELECT sid FROM sc GROUP BY sid HAVING AVG(score) > 60;
```

#### 2. 单行函数可以写在 WHERE 中

单行函数是逐行计算的，WHERE 阶段可以直接用单行函数加工字段后再做判断。

```
-- 正确写法：WHERE 中使用单行函数
SELECT * FROM sc WHERE ROUND(score, 0) > 60;
```

#### 3. 聚合函数不强制需要 GROUP BY

很多初学者以为聚合函数必须跟 GROUP BY 一起用，其实不是：

- 不写 GROUP BY：整张表默认是「一个大组」，聚合函数返回全表的汇总结果（1 行）；
- 写 GROUP BY：按字段分成多个小组，每个组返回一个聚合结果（组数 = 结果行数）。

### 五、常见误区澄清

1. ** `COUNT(*)` 和 `COUNT(字段)` 的区别**
    - `COUNT(*)`：统计总行数，不管字段是否为 NULL；
    - `COUNT(字段)`：统计该字段非空的行数，NULL 行不计数。 二者都是聚合函数，本质都是按组统计行数。
2. **带条件的聚合不是 WHERE 专利** 聚合函数内部也可以配合 `CASE WHEN` 实现带条件的统计，属于聚合+单行函数的组合用法：
    
    ```
    -- 统计每门课的及格人数
    SELECT cid, COUNT(CASE WHEN score>=60 THEN 1 END) AS 及格人数
    FROM sc
    GROUP BY cid;
    ```
