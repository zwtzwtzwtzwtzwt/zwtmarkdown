# InnoDB 什么时候自动创建索引

## 1. 定义主键 PRIMARY KEY → **自动创建聚集索引**

只要声明主键，一定会自动生成主键索引（聚集索引，名字固定叫 `PRIMARY`）

```
id bigint PRIMARY KEY
```

## 2. 定义 UNIQUE 唯一约束 → **自动创建唯一索引**

写 `UNIQUE` 约束，数据库自动建立唯一索引，用来保证唯一性校验。

```
phone varchar(11) UNIQUE
```

## 3. 添加外键 FOREIGN KEY（你刚才关心的重点）

> **条件：子表外键列，没有现成可用索引，InnoDB 自动新建普通索引；如果已有索引，不会新建。** ✅ 可用索引：普通索引、唯一索引、联合索引（**外键字段是联合索引最左前缀**） ❗ 只在**子表（从表 student）**自动建索引；**主表（被引用 grade 表）不会自动建索引，主表引用字段必须自己是主键/唯一索引**

例子：

```
ALTER TABLE student ADD CONSTRAINT fk_grade FOREIGN KEY(grade_id) REFERENCES grade(id);
```

- student 表 `grade_id` 没有索引 → **自动创建普通索引**，索引名默认和外键约束名一样
- student 表已经有 `KEY idx_grade(grade_id)` → **不会新建索引，直接复用**
- student 已有联合索引 `KEY idx_g_other(grade_id,other)` → grade_id 是最左前缀，满足，**不新建**

> 重点回顾：删除外键，**不会自动删除这个自动生成的索引**，需要单独 `DROP INDEX`，除非

## 4. 表没有主键，也没有非空唯一索引 → InnoDB 自动生成隐藏聚集索引

表完全没主键，也没有合适的 NOT NULL 唯一索引，InnoDB 内部自动生成隐藏的 `GEN_CLUST_INDEX`，基于 6 字节 row_id，**业务层面看不见，不能操作**。

## 5. 自适应哈希索引（Adaptive Hash Index）

InnoDB 内存里，频繁访问的索引页，**内存自动生成哈希索引**，不是磁盘上持久化的 B+树索引，不需要手动维护，一般面试不重点问。

# ❌ 不会自动创建索引的场景

1. 普通字段，只加 `NOT NULL / DEFAULT ''`，**不会自动建索引**
2. CHECK 约束，不会自动建索引
3. 主表（被引用表）的字段，建立外键不会自动给主表建索引（主表必须自己有主键/唯一索引，否则添加外键直接报错）

# 一句话面试背诵

定义主键会自动创建聚集索引；定义 UNIQUE 唯一约束自动创建唯一索引；添加外键时，如果子表外键列没有可用索引，InnoDB 自动新建普通索引，已有索引则复用；表无主键且无合适非空唯一索引，会生成隐藏聚集索引。普通字段、CHECK 约束不会自动建索引；外键删除不会连带删除自动生成的索引，需要单独删除索引。
