### 一、Maven 项目默认会打包哪些内容？

分两种场景：**普通标准 JAR 包** 和 **Spring Boot 可执行 JAR 包**（你当前的 Spring Boot 项目属于后者）。

#### 1. 普通标准 JAR（maven-jar-plugin 默认行为）

打包后 jar 包内部根目录结构：

- 所有 `.java` 文件编译后的 `.class` 文件，严格按照 Java 包路径层级存放
- `src/main/resources` 下的**所有文件和子目录**，原样复制到 jar 根目录
- `META-INF/` 目录：包含 `MANIFEST.MF`、pom 元数据文件等
- ❌ **不包含**任何第三方依赖 jar 包
- ❌ **不包含**测试代码、测试资源

#### 2. Spring Boot 可执行 JAR（spring-boot-maven-plugin 打包）

这是你项目实际使用的打包方式，采用「JAR 内嵌套 JAR」的结构，内部结构如下：

```
xxx.jar
├── BOOT-INF/
│   ├── classes/          # 你的业务代码 + 配置资源
│   │   ├── com/xxx/...   # 编译后的 .class 文件（对应 src/main/java）
│   │   └── *             # src/main/resources 下的所有文件原样复制
│   └── lib/              # 所有第三方依赖 jar 包
├── META-INF/             # 启动入口、清单文件
└── org/springframework/boot/loader/  # Spring Boot 启动器
```

一句话总结：** `src/main/java` + `src/main/resources` 的全部内容，最终都会出现在 `BOOT-INF/classes/` 里**。

### 二、resources 目录的详细处理规则

Maven 通过 `maven-resources-plugin` 插件在 `process-resources` 阶段处理资源文件，核心规则如下：

#### 1. 默认处理逻辑

- **默认资源目录**：只有 `src/main/resources` 被视为主资源目录
- **复制规则**：该目录下的所有文件、文件夹、层级结构，会**原样复制**到 `target/classes/` 目录，最终随打包进入 jar 包
- **路径对应**：`src/main/resources/application.yml` → 打包后对应 `BOOT-INF/classes/application.yml`
- **测试资源独立**：`src/test/resources` 仅用于单元测试，**不会打进主 jar 包**

#### 2. 资源过滤（Filtering）

默认关闭，开启后可以用 Maven 属性替换文件中的占位符（如 `${project.version}`）：

```
<build>
    <resources>
        <resource>
            <directory>src/main/resources</directory>
            <filtering>true</filtering> <!-- 开启占位符替换 -->
        </resource>
    </resources>
</build>
```

> 注意：图片、字体、压缩包等二进制文件不要开启过滤，会导致文件损坏。

#### 3. 常见坑点：java 目录下的资源文件会丢失

Maven 默认只把 `src/main/java` 当作源码目录，只编译 `.java` 文件，**该目录下的 .xml、.properties、.yml 等非 Java 文件会被直接忽略**，打包后会丢失。

如果你的 Mapper.xml 等文件习惯放在 java 目录下，需要手动配置资源目录：

```
<build>
    <resources>
        <!-- 保留原有的 resources 目录 -->
        <resource>
            <directory>src/main/resources</directory>
        </resource>
        <!-- 把 java 目录下的 xml 也当作资源打包 -->
        <resource>
            <directory>src/main/java</directory>
            <includes>
                <include>**/*.xml</include>
            </includes>
        </resource>
    </resources>
</build>
```

### 三、默认**不会**被打包的内容

1. **项目根目录下的文件/文件夹**：比如你之前的 `data/` 目录、`README.md`、`.gitignore`、`pom.xml` 等，都不会打进 jar 包
2. `src/test/` 下的所有代码和资源
3. `src/main/java` 下的非 Java 文件（除非手动配置资源目录）
4. 本地系统级依赖（除非特殊配置）
5. `target/` 目录下的临时编译文件

### 四、结合你文件存储场景的关键结论

1. **绝对不能把上传/分片文件放在 `resources` 目录下**：
    - 打包后资源在 jar 包内部，是**只读**的，无法写入、修改、新增文件
    - 这也是上一条回答里，把 `data/` 放在 jar 外部同级目录的根本原因
2. `data/` 目录放在项目根目录是正确方案：
    - 本地开发：项目根目录下的 `data/`，IDEA 启动直接读写
    - 打包部署：jar 包同级目录下的 `data/`，运行时自动创建，读写自由

### 五、常用的资源控制配置

如果需要自定义哪些文件打包、哪些不打包：

```
<build>
    <resources>
        <resource>
            <directory>src/main/resources</directory>
            <!-- 排除不需要打包的文件 -->
            <excludes>
                <exclude>**/*.test.yml</exclude>
                <exclude>dev-config/**</exclude>
            </excludes>
            <!-- 只打包指定文件/目录 -->
            <includes>
                <include>application.yml</include>
                <include>static/**</include>
            </includes>
        </resource>
    </resources>
</build>
```
