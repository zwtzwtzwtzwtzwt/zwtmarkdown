# Maven Java 项目：工作目录 & resources 详解

> 前提：标准 Maven 目录结构（`maven-archetype-quickstart`）

```
your-project/
├── pom.xml
├── src
│   ├── main
│   │   ├── java        # Java源码目录
│   │   └── resources   # 主程序资源文件
│   └── test
│       ├── java        # 测试代码
│       └── resources   # 测试资源文件
└── target              # 编译输出目录（自动生成）
```

## 一、什么是**工作目录（user.dir）**

Java 程序启动时的**当前工作目录**，对应系统属性 `System.getProperty("user.dir")`。 ✅ **不是 classpath，不是 resources 目录！**

- IDEA 直接运行 main 方法：`user.dir` = **项目根目录**（包含 pom.xml 那一层）
- `java -jar xxx.jar` 运行：`user.dir` = **执行 jar 命令所在的文件夹**
    
    > ⚠️ 坑：不要用 `new File("config.yml")` 直接读取 resources 文件，因为相对路径是相对于 `user.dir`，不是 resources！
    

示例：

```
// 打印工作目录
System.out.println(System.getProperty("user.dir"));
```

## 二、resources 目录（资源目录，属于 classpath）

Maven 会把 `src/main/resources` 下**所有文件**复制到 `target/classes`； `src/test/resources` 复制到 `target/test-classes`。

> 编译后，resources 里的文件**和编译后的.class 文件放在同一个目录 `classes` **，这个路径就是 **classpath**。

### 1. 读取 resources 资源（推荐方式，不受 user.dir 影响）

使用**类加载器**读取，从 classpath 加载：

```
// 方式1：当前类获取资源（推荐）
// / 代表 classpath根目录(target/classes)
InputStream is = Demo.class.getResourceAsStream("/config/application.yml");

// 方式2：类加载器，不带/
InputStream is = Demo.class.getClassLoader().getResourceAsStream("config/application.yml");
```

> ✅ 打包成 jar 后依然生效； ❌ 不要用 File 对象读取 resources 里的文件！打包进 jar 后，资源不再是磁盘上独立文件，File 会找不到。

### 2. resources 目录的作用

存放**非 Java 代码**的配置/静态文件：

- 配置文件：`application.yml`、`mybatis.xml`、`db.properties`
- 静态文本、模板、证书等 Maven 默认会把该目录标记为**资源根目录**，编译时自动拷贝到 classes。

## 三、工作目录 vs resources/classpath 核心区别

|项目|user.dir（工作目录）|resources（classpath）|
|---|---|---|
|含义|进程启动时所在文件夹|classpath，编译后在 target/classes|
|来源|操作系统启动位置|Maven 编译复制 src/main/resources|
|读取方式| `new File("xxx")` | `getResourceAsStream()` |
|Jar 包环境|命令执行目录|Jar 内部文件|
|典型场景|读写**外部文件**（日志、上传文件）|读取项目内置配置文件|

## 四、常见踩坑

### 坑 1：IDEA 运行正常，打包 jar 读取不到资源

原因：代码用 `new File("src/main/resources/xxx")`，打包后不存在 src 目录。 ✅ 解决：改用 `getResourceAsStream()`。

### 坑 2：资源文件没有被打包进 target/classes

原因：pom 资源过滤配置丢失，或者文件名特殊。 默认 Maven 已经处理 resources；如果需要手动配置：

```
<build>
    <resources>
        <resource>
            <directory>src/main/resources</directory>
            <!-- 是否开启变量替换，比如${} -->
            <filtering>true</filtering>
        </resource>
    </resources>
</build>
```

### 坑 3：区分 main/resources 和 test/resources

- 执行单元测试：classpath 优先加载 `test/resources`，会覆盖 main 里同名文件
- 打包：**test/resources 不会打进最终 jar**

## 五、快速记忆一句话

> `user.dir` = 你在哪敲 java 命令； `resources` 的文件编译后进 classpath，要用流读取，**不要当本地文件读**。
