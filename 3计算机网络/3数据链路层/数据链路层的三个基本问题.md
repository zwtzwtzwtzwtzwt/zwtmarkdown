# 数据链路层 3 个基本问题（谢希仁教材 + 408 考点）

> 原文：**封装成帧、透明传输、差错检测**

## 1. 封装成帧（解决）

在一段**数据的前后**添加**帧首部 + 帧尾部**，构成一个帧。

- 首部尾部作用：**标记帧的开始和结束**，让接收方知道：一帧从哪里开始、到哪里结束。
- 例子：以太网帧，有**前导码（首部）、FCS 校验（尾部）**
- 本质：把网络层交付的**IP 分组**，包装成链路层能识别的帧。

## 2. 透明传输

含义：**不管传输的数据是什么比特组合，都可以原样传送，不会被误判成帧的起止标记**。

- 问题：如果数据里恰好出现了和**帧定界符（标志字节）一模一样**的比特，接收端会误以为帧提前结束。
- 解决办法：**字节填充（字符填充）** 发送端：数据里遇到标志字节，在前面插入转义字符； 接收端：收到转义字符就删掉，后面字节原样接收。
    
    > “透明”：对上层用户完全看不见这个填充操作，上层感知不到处理过程。
    

## 3. 差错检测

检测传输过程中比特出错（0 变 1、1 变 0），**不纠正错误（只检错，纠错是可选的，不是基本问题）**

- 经典方案：**CRC 循环冗余校验**
- 原理：发送方算出 FCS（帧检验序列）放在帧尾部；接收方校验，判断帧是否出错。
    
    > ⚠️重点坑点：CRC**只能检错，不能纠错**；检错不能做到 100%（有漏检概率，但概率极低）。

# 408 选择题高频辨析

1. 三个基本问题**只包含：封装成帧、透明传输、差错检测** ❌ 不属于三个基本问题：流量控制、可靠传输、MAC 访问控制、重传。
    
    > 可靠传输、流量控制是**可选功能**（比如 PPP 协议不可靠，以太网也不做可靠传输），**不是链路层必须解决的 3 个基础问题**。 以太网：只完成封装成帧、透明传输、CRC 差错检测，**不做重传，不可靠**。
    

## 一句话速记口诀

**封帧、透传、差错检**

### 补充区分（极易混淆）

- 链路层**三个基本问题**：所有链路层协议都要解决（PPP、以太网都有）
- 链路层**可靠传输（确认+重传+流量控制）**：**不是基本问题**，只是部分协议（如停止等待、HDLC）才实现。
