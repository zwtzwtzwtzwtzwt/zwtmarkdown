### 一、发送方向（自上而下封装）：表述基本正确

发送端数据自上而下逐层封装，每一层都遵循：

1. 接收**上一层交付的 PDU**，将其作为**本层的 SDU**（服务数据单元，即本层要传输的净荷）；
2. 在本层 SDU 的基础上，添加**本层的 PCI（协议控制信息，即首部/尾部）**，封装生成**本层的 PDU**（协议数据单元）；
3. 将本层 PDU 向下传递给下一层，它就成为了**下一层的 SDU**；
4. 下一层重复上述封装过程，直到最底层（数据链路层）将 PDU 发送到物理介质。

核心等式（发送端）： $$\text{上层PDU} = \text{本层SDU}$$ $$\text{本层PDU} = \text{本层SDU} + \text{本层PCI}$$ $$\text{本层PDU} = \text{下层SDU}$$

---

### 二、接收方向（自下而上解封装）：原表述有错误


接收端数据自下而上逐层解封装，每一层都遵循：

1. 从下一层接收**本层的 PDU**；
2. 剥去本层 PDU 中的本层 PCI，解析控制信息，得到**本层的 SDU**；
3. 将本层 SDU 向上交付给上一层，它就成为了**上一层的 PDU**；
4. 上一层重复上述解封装过程，直到最高层（应用层）得到原始用户数据。

核心等式（接收端）： $$\text{本层PDU} \xrightarrow{\text{去掉本层PCI}} \text{本层SDU}$$ $$\text{本层SDU} = \text{上层PDU}$$

---

### 三、一句话总结核心对应关系

**永远成立：上层的 PDU = 下层的 SDU**

**核心恒等式（相邻两层间永远成立）**：上一层的协议数据单元（PDU）= 下一层的服务数据单元（SDU）

- **发送端（自上而下封装）**：上层将本层封装完成的 PDU 向下交付，下层将其作为本层的 SDU；添加上本层的协议控制信息（PCI，即协议首部/尾部）后，生成本层的 PDU，继续向下层传递，逐层封装直至物理层转换为比特流。
- **接收端（自下而上解封装）**：下层对接收到的本层 PDU，剥去自身的 PCI 后得到本层的 SDU；该 SDU 向上交付后，就是上层的 PDU；上层继续执行解封装操作，逐层向上还原，直至应用层得到原始业务数据。

---



# 全部流程  

采用**TCP/IP 五层教学模型**（从上到下：应用层→传输层→网络层→数据链路层→物理层），以「主机 A 的浏览器向主机 B 的 Web 服务器发送 HTTP 请求」为场景，完整走一遍**封装→传输→解封装**的端到端流程。

为对应之前的公式，约定层级编号：

- 第 5 层：应用层
- 第 4 层：传输层
- 第 3 层：网络层
- 第 2 层：数据链路层
- 第 1 层：物理层

全程遵循核心规则：

> **上层 PDU = 本层 SDU**    **本层 PDU = 本层 SDU + 本层 PCI**       **本层 PDU = 下层 SDU**

---

## 一、发送端（主机 A）：自上而下逐层封装

数据从应用程序产生，逐层向下添加协议控制信息（PCI），最终变成比特流发往物理链路。

### 第 5 层：应用层

- **本层 SDU**：浏览器产生的原始业务数据（比如请求的 URL、参数），假设大小为 800 B
- **本层 PCI**：HTTP 协议首部（包含请求方法、版本、主机名等控制信息），假设大小为 200 B
- **本层 PDU**：HTTP 报文（完整的应用层协议数据单元） 大小 = 800 B + 200 B = 1000 B
- 向下传递：HTTP 报文交给传输层，成为**传输层的 SDU**

### 第 4 层：传输层（TCP 协议）

- **本层 SDU**：上层交付的 HTTP 报文（1000 B），也就是第 5 层的 PDU
- **本层 PCI**：TCP 首部（包含源 / 目的端口、序号、确认号、窗口等控制信息），固定首部 20 B
- **本层 PDU**：TCP 段（Segment，传输层协议数据单元） 大小 = 1000 B + 20 B = 1020 B
- 向下传递：TCP 段交给网络层，成为**网络层的 SDU**

### 第 3 层：网络层（IP 协议）

- **本层 SDU**：上层交付的 TCP 段（1020 B），也就是第 4 层的 PDU
- **本层 PCI**：IP 首部（包含源 / 目的 IP 地址、TTL、协议号等控制信息），固定首部 20 B
- **本层 PDU**：IP 分组 / IP 包（Packet，网络层协议数据单元） 大小 = 1020 B + 20 B = 1040 B
- 向下传递：IP 分组交给数据链路层，成为**数据链路层的 SDU**

### 第 2 层：数据链路层（以太网协议）

- **本层 SDU**：上层交付的 IP 分组（1040 B），也就是第 3 层的 PDU
- **本层 PCI**：以太网帧首部（14 B，含源 / 目的 MAC 地址、类型） + 帧尾部 FCS 校验（4 B），共 18 B
- **本层 PDU**：以太网帧（Frame，数据链路层协议数据单元） 大小 = 1040 B + 18 B = 1058 B
- 向下传递：以太网帧交给物理层

### 第 1 层：物理层

物理层不进行协议封装，也不定义 SDU/PCI：

- 接收链路层交付的完整数据帧，将其逐比特转换为电信号 / 光信号
- **本层 PDU**：比特（bit）
- 通过网线 / 光纤等物理介质，将比特流发送到主机 B

---

## 二、接收端（主机 B）：自下而上逐层解封装

比特流从物理介质到达主机 B，逐层向上剥去对应层的协议控制信息，最终把原始数据交给应用程序。

### 第 1 层：物理层

- 从物理介质接收比特流，还原出完整的以太网帧
- 将帧交付给数据链路层，成为**数据链路层的 PDU**

### 第 2 层：数据链路层（以太网协议）

- **本层 PDU**：物理层交付的以太网帧（1058 B）
- 处理过程：校验 FCS、解析帧首部，确认帧是发给本机的
- 剥去**本层 PCI**（14 B 帧头 + 4 B 帧尾），得到**本层 SDU**：IP 分组（1040 B）
- 向上传递：IP 分组交给网络层，成为**网络层的 PDU**

### 第 3 层：网络层（IP 协议）

- **本层 PDU**：链路层交付的 IP 分组（1040 B）
- 处理过程：解析 IP 首部，校验 IP 地址、TTL，确认分组是发给本机的
- 剥去**本层 PCI**（20 B IP 首部），得到**本层 SDU**：TCP 段（1020 B）
- 向上传递：TCP 段交给传输层，成为**传输层的 PDU**

### 第 4 层：传输层（TCP 协议）

- **本层 PDU**：网络层交付的 TCP 段（1020 B）
- 处理过程：解析 TCP 首部，根据端口号找到对应的应用进程，校验序号、校验和
- 剥去**本层 PCI**（20 B TCP 首部），得到**本层 SDU**：HTTP 报文（1000 B）
- 向上传递：HTTP 报文交给应用层，成为**应用层的 PDU**

### 第 5 层：应用层

- **本层 PDU**：传输层交付的 HTTP 报文（1000 B）
- 处理过程：解析 HTTP 首部（200 B），提取出里面的业务请求数据
- 最终得到**本层 SDU**：原始的 HTTP 请求数据（800 B），交给 Web 服务器应用程序
- 至此，一次完整的端到端数据传输完成

---

## 三、全过程核心规律总结

1. **对称对应**：发送端封装时添加了什么 PCI，接收端解封装时就剥去什么 PCI；同层的 PCI 长度、格式完全一致。
2. **层间恒等式**：无论发送还是接收，永远满足「**上一层的 PDU = 下一层的 SDU**」。
3. **数据透明性**：除了本层的 PCI 会被添加 / 移除，中间的 SDU（净荷）在传输过程中不会被修改，完整透明地从源端传到目的端。
4. **物理层特殊**：物理层只负责比特传输，不做封装解封装，因此没有 SDU/PCI 的概念，是五层里唯一不参与封装的层级。
这是计算机网络分层架构的核心思想，简单说就是：**下层向上一层承诺并提供标准化的数据传输能力，上层只需要使用这个能力，不用关心下层具体怎么实现**。下面结合你之前学的SDU/PDU、封装解封装知识，完整拆解清楚。

---

### 一、「下层为上层提供服务」的本质

服务是**垂直方向**（层与层之间）的能力交付，核心是三点：

1. **服务对象是上层的数据** 上层把需要传输的数据（也就是上层的PDU）交给下层，对下层来说这就是自己的SDU（服务数据单元）。下层的任务，就是把这份SDU，完整、准确地送到对端对应的上层。
2. **实现过程对上层透明** 上层完全不用关心下层的工作细节：不用管数据走了哪条路由、用了什么编码、有没有出错重传、经过了多少个节点。对上层来说，效果就是“我把数据发出去，对端的同层就收到了”。
3. **服务有明确的接口约定** 下层通过层间接口向上层提供一组固定的功能（比如“发送数据”“接收数据”），上层只能通过约定好的接口使用服务，不能越过接口直接操作下层的内部逻辑。

---

### 二、服务是怎么实现的？

下层能向上层提供服务，靠的是**「本层的协议」 + 「更下层提供的服务」**。 举个例子：网络层（IP层）给传输层提供服务

- 它先利用**数据链路层提供的帧传输服务**，把数据送到下一个路由器；
- 同时它遵守**IP协议**（对等层之间的水平规则），进行路由选择、分组转发；
- 最终把传输层交下来的SDU，跨网络送到目的主机的传输层。

对应你熟悉的封装过程： 下层把上层的SDU加上本层PCI（协议控制信息），封装成本层PDU，通过物理链路传到对端；对端下层再解封装，还原出SDU交给对端上层。 **这个完整的“封装→传输→解封装”流程，就是下层为上层提供服务的过程**。

---

### 三、关键辨析：服务 vs 协议

这是计网分层最容易混淆的一对概念，也是常考点：

|概念|方向|作用对象|本质|
|---|---|---|---|
|**服务**|垂直方向（下层→上层）|相邻两层之间|对外暴露的能力、层间的接口约定|
|**协议**|水平方向（本端↔对端）|同层的对等实体之间|通信的规则、格式、顺序约定|

一句话总结： **协议是实现服务的内部手段，服务是协议对外呈现的最终能力**。

---

### 四、结合五层模型的具体例子

从上到下，每一层都在为自己的上一层提供服务：

1. **物理层 → 数据链路层** 提供「透明比特传输服务」：帮链路层把0/1比特流从线缆一端传到另一端，不用关心这些比特代表什么含义。
2. **数据链路层 → 网络层** 提供「相邻节点帧交付服务」：帮网络层把IP分组，从同一个链路里的一个节点，可靠传到下一个节点。
3. **网络层 → 传输层** 提供「跨网络分组路由服务」：帮传输层把数据段，从源主机经过任意网络路径，送到目的主机。
4. **传输层 → 应用层** 提供「端到端进程通信服务」：帮应用程序把数据从源端口送到目的端口，还可以附加可靠传输、流量控制、拥塞控制等增强能力。
5. **应用层 → 用户** 提供具体的网络业务服务，比如网页浏览、文件传输、邮件收发等。

---

### 五、回到你之前的核心公式

**上层的PDU = 下层的SDU** 这个等式背后，就是“下层为上层提供服务”的体现： 上层把自己要传输的完整数据（PDU）交给下层，这份数据就成了下层的服务对象（SDU）；下层负责把它传输到对端，再交还给对端的上层。整个过程中，下层不修改SDU的内容，只添加自己的控制信息（PCI）来完成传输服务。
