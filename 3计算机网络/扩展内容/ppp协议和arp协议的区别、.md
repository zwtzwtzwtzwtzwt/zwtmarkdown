# PPP 和 ARP 的核心区别

一句话：**PPP 是广域网链路层协议（点到点）；ARP 是局域网地址解析协议（IP→MAC）**，二者工作场景、目的完全不一样。

## 1. 基础定位对比

|项目|PPP|ARP|
|---|---|---|
|**所属层级**|数据链路层（链路层）|数据链路层辅助协议（基于 IP，工作在二层/三层之间）|
|**使用场景**|**点到点链路**：拨号、串口、光纤点对点，两端直接相连，没有广播域  <br>例：老式 ADSL 拨号、路由器串口链路|**广播型局域网**（以太网）  <br>例：电脑、交换机组成的 LAN|
|**核心作用**|在点到点链路上**封装 IP 报文**，完成链路建立、认证、配置协商（IP 地址协商）|**地址解析**：已知目标 IP，查询对应的 MAC 地址|
|**网络模型**|链路层承载协议|IP 配套解析协议|

## 2. 原理细节

### PPP（Point-to-Point Protocol，点到点协议）

1. 链路是**一对一**，不存在 MAC 地址，不需要 MAC 寻址；
2. 分为三个阶段：**链路建立(LCP) → 认证(PAP/CHAP) → 网络层协商(NCP)**；
3. NCP 可以协商给两端分配 IP；
4. 帧结构里**没有 MAC 地址字段**，只需要标识是 PPP 帧即可。

> 重点：PPP 链路**根本没有 MAC 地址**，所以这条链路上**不会跑 ARP**！

### ARP（Address Resolution Protocol，地址解析协议）

1. 运行在**以太网这类广播网络**；以太网通信必须依靠 MAC 地址；
2. 主机发 ARP 广播：“谁是这个 IP？请把你的 MAC 发给我”；
3. 目标主机单播回复 ARP 应答；
4. 主机本地维护 ARP 缓存表（IP-MAC 映射）；
5. **ARP 只用于同一个广播域内**，跨网段 ARP 无效。

## 3. 最关键的几个区分点

1. **有没有 MAC**
    - PPP 点到点链路：**无 MAC，不需要 ARP**
    - 以太网：有 MAC，必须 ARP 做 IP 转 MAC
2. **寻址方式**
    - PPP：点到点，链路两端直连，不需要二层地址寻址
    - ARP：为以太网二层 MAC 寻址服务
3. **报文方向**
    - PPP：封装 IP 包，负责把 IP 包从一端送到另一端
    - ARP：单独的控制报文，**不是用来传输业务 IP 数据**，只做地址查询

## 4. 简单举例理解

- 家里早年宽带拨号：电脑 ↔ 运营商 BRAS，中间是 PPP 链路。这条链路**没有 MAC，不会 ARP**，PPP 通过 NCP 协商拿到公网 IP。
- 电脑连家用交换机（以太网局域网）：电脑要访问同网段另一台电脑，先发 ARP 广播拿到对方 MAC，再封装以太网帧发送。

## 5. 易混考点总结（408 常考）

✅ PPP：数据链路层，点对点，无 MAC，LCP/NCP，PAP/CHAP，**不使用 ARP** ✅ ARP：IP 配套协议，以太网广播域，IP→MAC，**不能在 PPP 链路上运行**

> 补充：如果 PPP 链路两端后面接以太网，那是**以太网网段内部跑 ARP**，PPP 链路本身依旧没有 ARP。
