要彻底理解内网穿透的原理，必须先搞懂它要突破的核心障碍——**NAT（网络地址转换）的入站拦截机制**，再分两种主流技术路线拆解：**中转隧道模式**（通用性最强，frp/ngrok 等工具采用）和**P 2 P 打洞模式**（无中转，TeamViewer/向日葵等采用）。

## 一、前置核心：NAT 的工作机制与入站拦截本质

家用宽带、企业内网、校园网环境下，设备都在路由器后方，使用私有 IP（192.168.x.x/10.x.x.x/172.16-31.x.x）。路由器通过 NAT 技术，让所有内网设备共用一个或少量公网 IP 对外通信。

### 1. NAPT 的核心：映射表与单向放行

家用路由器普遍使用**NAPT（网络地址端口转换）**，它会维护一张「NAT 映射表」，记录着： `内网IP:内网端口 ↔ 公网IP:公网端口 ↔ 目标外部IP:目标外部端口`

它的工作逻辑是**严格的“出站主动，入站响应”**：

- 当内网设备主动向外网发起连接时，路由器自动生成一条映射记录，把内网地址转换成公网地址发出去；
- 当外网返回数据包时，路由器查映射表，匹配到对应内网设备，转发回去；
- 如果外网主动向公网 IP 发起连接，路由器查不到对应的映射记录，**直接丢弃数据包**，这就是外网无法直接访问内网的根本原因。

### 2. NAT 的 4 种类型（决定穿透难度）

不同网络环境的 NAT 策略严格程度不同，直接影响 P 2 P 穿透的成功率，从宽松到严格分为：

|NAT 类型|映射规则|入站放行规则|常见场景|
|---|---|---|---|
|完全锥形（Full Cone）|同一内网 IP:端口，永久映射到固定公网 IP:端口|任何外网主机都能向该公网地址发数据|少数企业宽带、早期家用宽带|
|限制锥形（Restricted Cone）|映射固定不变|只有内网主动访问过的外部 IP，才能发数据入站|部分家用路由器|
|端口限制锥形（Port Restricted Cone）|映射固定不变|只有内网主动访问过的外部 IP+端口，才能发数据入站|绝大多数家用路由器|
|对称型（Symmetric）|同一内网端口，访问不同外部地址时，映射到不同的公网端口|只有内网主动访问过的 IP+端口，才能发数据入站|运营商 CGNAT、企业严格内网|

### 3. 雪上加霜：运营商 CGNAT（大内网）

现在多数家庭宽带没有独立公网 IP，运营商会在小区/市级层面再做一层 NAT（运营商级 NAT，CGNAT），形成**“用户路由器 NAT + 运营商 NAT”**的双层 NAT 结构。 此时你查到的“外网 IP”本质上还是运营商内网的 IP，外层还有一层 NAT 设备，即使手动在路由器配置端口映射，外层运营商的 NAT 依然会拦截入站连接，外网根本无法到达你的路由器。

## 二、主流方案：中转隧道式内网穿透原理

这是目前通用性最强、成功率 100%的内网穿透方案，**frp、ngrok、cpolar、花生壳**等绝大多数工具都基于此架构，也叫「反向代理隧道模式」。

### 1. 核心思想

既然 NAT 拒绝外网主动发起的入站连接，但允许内网主动发起的出站连接，那就**让内网设备主动向外网的一台公网服务器建立一条持久的“隧道”**，所有外网访问都先打到公网服务器，再通过隧道转发进内网。

本质是：把外网的入站请求，变成公网服务器通过已有隧道发往内网的“出站响应数据”，从而绕过 NAT 的入站拦截。

### 2. 架构组成

整套系统分为三个角色：

- **内网客户端（Client）**：运行在内网设备上，主动向公网服务器发起连接，建立并维持隧道；
- **公网中转服务器（Server）**：拥有独立公网 IP，对外暴露端口接收外网请求，对内和内网客户端维持隧道；
- **外网访问者（Visitor）**：想要访问内网服务的用户/设备。

### 3. 完整工作流程（以 TCP 服务穿透为例）

#### 步骤 1：建立控制隧道（长连接）

内网客户端启动后，**主动向公网服务器的指定端口（比如 frp 的 7000 端口）发起 TCP 连接**，建立一条持久的「控制通道」。

- 因为是内网主动出站，路由器和运营商的 NAT 都会放行，并在 NAT 映射表中保留这条连接的条目，允许服务器随时回传数据；
- 客户端会定期发送心跳包，维持隧道不被 NAT 设备因超时断开。

#### 步骤 2：注册端口映射规则

客户端通过控制通道，向服务器发送要穿透的服务配置，比如：

> “请把你服务器的 8080 端口，收到的所有 TCP 数据，都通过隧道转发给我，我再转给本地的 80 端口（内网 Web 服务）”

服务器收到后，在本地监听对应的 8080 端口，等待外网访问。

#### 步骤 3：外网用户发起访问

外网用户在浏览器输入 `公网服务器IP:8080`，向公网服务器发起 TCP 连接请求。

#### 步骤 4：流量中转转发

1. 公网服务器收到外网请求后，通过「控制通道」通知内网客户端：“有新的访问请求，需要建立数据连接”；
2. 内网客户端收到通知，**主动向公网服务器发起一条新的数据连接**（同样是出站连接，NAT 放行）；
3. 服务器把外网请求的数据包，通过这条数据隧道转发给内网客户端；
4. 内网客户端收到数据后，转发给本地的目标服务（比如本地 127.0.0.1:80 的 Web 服务）；
5. 本地服务的响应数据，原路返回：内网客户端 → 数据隧道 → 公网服务器 → 外网用户。

至此，一次完整的外网访问内网服务就完成了。

> 进阶优化：主流工具都支持**TCP 多路复用**，多个请求可以共用同一条隧道连接，减少连接建立开销，提升速度。

### 4. 特殊场景：HTTP/HTTPS 域名穿透

如果要穿透多个 Web 服务，不需要占用多个端口，可以利用 HTTP 协议的 `Host` 主机头实现：

- 公网服务器监听 80/443 端口；
- 外网用户访问不同的域名（比如 `a.example.com`、`b.example.com`），都解析到公网服务器 IP；
- 服务器根据请求头中的 `Host` 字段，判断该请求对应哪个内网服务，再通过对应的隧道转发进去。

这就是为什么很多内网穿透工具支持自定义域名、子域名，本质是在公网服务器做了一层**反向代理**。

### 5. 为什么能穿透所有 NAT（包括 CGNAT）

因为整个过程中，**所有从外到内的连接，都是内网客户端主动发起的出站连接**，NAT 设备只会看到“内网设备主动连了公网服务器，服务器在回数据”，完全符合 NAT 的放行规则。 哪怕是多层 CGNAT，只要能正常访问外网（能主动出站），就能建立隧道，实现穿透。

## 三、无中转方案：P 2 P NAT 打洞原理

除了中转模式，还有一种不需要公网中转服务器的技术：**NAT 打洞（Hole Punching）**，也叫点对点（P 2 P）穿透，常用于远程控制软件（TeamViewer、向日葵）、即时通讯文件传输（QQ/微信）、P 2 P 下载等场景。

### 1. 核心思想

让**内网两端的设备都主动向对方发起出站连接**，在各自的 NAT 设备上“打一个洞”，让对方的数据包能通过这个洞进来，最终实现两端直连，不需要中间服务器转发流量。

### 2. 前置辅助：STUN 协议

要打洞，两端首先得知道对方的**公网映射地址（公网 IP+公网端口）**，但内网设备自己不知道 NAT 把自己映射成了什么公网地址，这就需要**STUN 服务器**（会话穿透实用工具）来帮忙。

STUN 服务器的作用很简单：

- 内网设备主动给 STUN 服务器发一个数据包；
- STUN 服务器收到后，把数据包里的源地址（也就是 NAT 映射后的公网 IP+端口）返回给内网设备；
- 这样内网设备就知道了自己在公网上的映射地址。

### 3. 完整打洞流程（以两端都是端口限制锥形 NAT 为例）

假设有 A、B 两个内网设备，都在各自的 NAT 后面，想要直接通信：

#### 步骤 1：获取各自公网映射地址

A 和 B 分别主动向 STUN 服务器发送请求，获取到自己的公网映射地址：

- A 得到自己的公网地址：`IP_A:PORT_A`
- B 得到自己的公网地址：`IP_B:PORT_B`

#### 步骤 2：交换地址信息

A 和 B 通过一个第三方的「信令服务器」，互相交换对方的公网映射地址（信令服务器只负责传消息，不转发数据流量）。

#### 步骤 3：同时发起打洞包

A 和 B**同时向对方的公网地址发送一个 UDP 数据包**（出站连接）：

- A 发送数据包到 `IP_B:PORT_B`，这个包会到达 B 的 NAT 设备；
- B 发送数据包到 `IP_A:PORT_A`，这个包会到达 A 的 NAT 设备。

#### 步骤 4：打洞成功

- 对于 A 的 NAT 来说：A 主动给 `IP_B:PORT_B` 发了包，所以 NAT 会放行来自 `IP_B:PORT_B` 的入站包；
- 对于 B 的 NAT 来说：B 主动给 `IP_A:PORT_A` 发了包，所以 NAT 会放行来自 `IP_A:PORT_A` 的入站包；

此时，两边的 NAT 都已经“放行”了对方的地址，隧道就打通了，A 和 B 可以直接通过公网映射地址互相通信，不需要任何中转。

### 4. 打洞成功率与 NAT 类型的关系

NAT 打洞并不是 100%成功，成功率完全取决于两端的 NAT 类型：

- 锥型 NAT ↔ 锥型 NAT：几乎 100%成功；
- 锥型 NAT ↔ 对称型 NAT：有概率成功，需要端口预测；
- 对称型 NAT ↔ 对称型 NAT：几乎无法打洞成功，因为每次访问不同地址，公网端口都会变，对方无法预测。

这也是为什么远程控制软件有时候速度快（直连成功），有时候速度慢（打洞失败，走中转）。

### 5. 打洞失败的降级方案

如果 P 2 P 打洞失败，系统会自动降级为**中转服务器转发模式**，和前面讲的中转隧道原理一样，保证可用性，只是流量会经过服务器，速度取决于服务器带宽。

## 四、易混淆概念辨析

### 1. 内网穿透 vs 路由器端口映射（DMZ）

很多人会把路由器的「端口映射/虚拟服务器/DMZ」和内网穿透混淆，二者本质完全不同：

|对比项|路由器端口映射|内网穿透（中转模式）|
|---|---|---|
|核心逻辑|在路由器 NAT 表手动加固定映射，让入站连接直接转发到内网设备|内网主动出站建隧道，通过公网服务器中转流量|
|前提条件|路由器必须有**真正的公网 IP**|只要能上网就行，有无公网 IP 都可以|
|CGNAT 环境|完全无效，外层运营商 NAT 依然拦截|正常使用，不受影响|
|配置位置|需要登录路由器后台配置|只需要在内网设备装客户端|
|网络环境|只能在自己可控的路由器下使用|任何网络（校园网、公司网、4 G/5 G）都能用|

简单说：**有公网 IP，用端口映射；没有公网 IP，用内网穿透**。

### 2. 有公网 IP 还需要内网穿透吗？

如果有固定公网 IP，端口映射就能满足需求，不需要内网穿透；但如果是动态公网 IP（每次重启路由器 IP 就变），可以配合 DDNS（动态域名解析）使用，也比内网穿透速度更快、延迟更低。

## 总结

- 内网穿透的核心目标：突破 NAT 的入站拦截，让外网能访问内网服务；
- 中转隧道模式：通用性最强，靠公网服务器中转，100%成功，适合部署长期服务；
- P 2 P 打洞模式：无中转、速度快，但成功率受 NAT 类型限制，适合临时传输、远程控制。
