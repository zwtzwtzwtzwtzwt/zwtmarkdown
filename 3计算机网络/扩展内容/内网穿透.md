要彻底理解内网穿透的原理，必须先搞懂它要突破的核心障碍——**NAT（网络地址转换）的入站拦截机制**，再分两种主流技术路线拆解：**中转隧道模式**（通用性最强，frp/ngrok 等工具采用）和**P 2 P 打洞模式**（无中转，TeamViewer/向日葵等采用）。

## 一、前置核心：NAT 的工作机制与入站拦截本质

家用宽带、企业内网、校园网环境下，设备都在路由器后方，使用私有 IP（192.168.x.x/10.x.x.x/172.16-31.x.x）。路由器通过 NAT 技术，让所有内网设备共用一个或少量公网 IP 对外通信。

### 1. NAPT 的核心：映射表与单向放行

家用路由器普遍使用**NAPT（网络地址端口转换）**，它会维护一张「NAT 映射表」，记录着： `内网IP:内网端口 ↔ 公网IP:公网端口 ↔ 目标外部IP:目标外部端口`

它的工作逻辑是**严格的“出站主动，入站响应”**：

- 当内网设备主动向外网发起连接时，路由器自动生成一条映射记录，把内网地址转换成公网地址发出去；
- 当外网返回数据包时，路由器查映射表，匹配到对应内网设备，转发回去；
- 如果外网主动向公网 IP 发起连接，路由器查不到对应的映射记录，**直接丢弃数据包**，这就是外网无法直接访问内网的根本原因。

### 2. NAT 的 4 种类型（决定穿透难度）

不同网络环境的 NAT 策略严格程度不同，直接影响 P 2 P 穿透的成功率，从宽松到严格分为：

|NAT 类型|映射规则|入站放行规则|常见场景|
|---|---|---|---|
|完全锥形（Full Cone）|同一内网 IP:端口，永久映射到固定公网 IP:端口|任何外网主机都能向该公网地址发数据|少数企业宽带、早期家用宽带|
|限制锥形（Restricted Cone）|映射固定不变|只有内网主动访问过的外部 IP，才能发数据入站|部分家用路由器|
|端口限制锥形（Port Restricted Cone）|映射固定不变|只有内网主动访问过的外部 IP+端口，才能发数据入站|绝大多数家用路由器|
|对称型（Symmetric）|同一内网端口，访问不同外部地址时，映射到不同的公网端口|只有内网主动访问过的 IP+端口，才能发数据入站|运营商 CGNAT、企业严格内网|

### 3. 雪上加霜：运营商 CGNAT（大内网）

现在多数家庭宽带没有独立公网 IP，运营商会在小区/市级层面再做一层 NAT（运营商级 NAT，CGNAT），形成**“用户路由器 NAT + 运营商 NAT”**的双层 NAT 结构。 此时你查到的“外网 IP”本质上还是运营商内网的 IP，外层还有一层 NAT 设备，即使手动在路由器配置端口映射，外层运营商的 NAT 依然会拦截入站连接，外网根本无法到达你的路由器。

## 二、主流方案：中转隧道式内网穿透原理

这是目前通用性最强、成功率 100%的内网穿透方案，**frp、ngrok、cpolar、花生壳**等绝大多数工具都基于此架构，也叫「反向代理隧道模式」。

### 1. 核心思想

既然 NAT 拒绝外网主动发起的入站连接，但允许内网主动发起的出站连接，那就**让内网设备主动向外网的一台公网服务器建立一条持久的“隧道”**，所有外网访问都先打到公网服务器，再通过隧道转发进内网。

本质是：把外网的入站请求，变成公网服务器通过已有隧道发往内网的“出站响应数据”，从而绕过 NAT 的入站拦截。

### 2. 架构组成

整套系统分为三个角色：

- **内网客户端（Client）**：运行在内网设备上，主动向公网服务器发起连接，建立并维持隧道；
- **公网中转服务器（Server）**：拥有独立公网 IP，对外暴露端口接收外网请求，对内和内网客户端维持隧道；
- **外网访问者（Visitor）**：想要访问内网服务的用户/设备。

### 3. 完整工作流程（以 TCP 服务穿透为例）

#### 步骤 1：建立控制隧道（长连接）

内网客户端启动后，**主动向公网服务器的指定端口（比如 frp 的 7000 端口）发起 TCP 连接**，建立一条持久的「控制通道」。

- 因为是内网主动出站，路由器和运营商的 NAT 都会放行，并在 NAT 映射表中保留这条连接的条目，允许服务器随时回传数据；
- 客户端会定期发送心跳包，维持隧道不被 NAT 设备因超时断开。

#### 步骤 2：注册端口映射规则

客户端通过控制通道，向服务器发送要穿透的服务配置，比如：

> “请把你服务器的 8080 端口，收到的所有 TCP 数据，都通过隧道转发给我，我再转给本地的 80 端口（内网 Web 服务）”

服务器收到后，在本地监听对应的 8080 端口，等待外网访问。

#### 步骤 3：外网用户发起访问

外网用户在浏览器输入 `公网服务器IP:8080`，向公网服务器发起 TCP 连接请求。

#### 步骤 4：流量中转转发

1. 公网服务器收到外网请求后，通过「控制通道」通知内网客户端：“有新的访问请求，需要建立数据连接”；
2. 内网客户端收到通知，**主动向公网服务器发起一条新的数据连接**（同样是出站连接，NAT 放行）；
3. 服务器把外网请求的数据包，通过这条数据隧道转发给内网客户端；
4. 内网客户端收到数据后，转发给本地的目标服务（比如本地 127.0.0.1:80 的 Web 服务）；
5. 本地服务的响应数据，原路返回：内网客户端 → 数据隧道 → 公网服务器 → 外网用户。

至此，一次完整的外网访问内网服务就完成了。

> 进阶优化：主流工具都支持**TCP 多路复用**，多个请求可以共用同一条隧道连接，减少连接建立开销，提升速度。

### 4. 特殊场景：HTTP/HTTPS 域名穿透

如果要穿透多个 Web 服务，不需要占用多个端口，可以利用 HTTP 协议的 `Host` 主机头实现：

- 公网服务器监听 80/443 端口；
- 外网用户访问不同的域名（比如 `a.example.com`、`b.example.com`），都解析到公网服务器 IP；
- 服务器根据请求头中的 `Host` 字段，判断该请求对应哪个内网服务，再通过对应的隧道转发进去。

这就是为什么很多内网穿透工具支持自定义域名、子域名，本质是在公网服务器做了一层**反向代理**。

### 5. 为什么能穿透所有 NAT（包括 CGNAT）

因为整个过程中，**所有从外到内的连接，都是内网客户端主动发起的出站连接**，NAT 设备只会看到“内网设备主动连了公网服务器，服务器在回数据”，完全符合 NAT 的放行规则。 哪怕是多层 CGNAT，只要能正常访问外网（能主动出站），就能建立隧道，实现穿透。

## 三、无中转方案：P 2 P NAT 打洞原理

除了中转模式，还有一种不需要公网中转服务器的技术：**NAT 打洞（Hole Punching）**，也叫点对点（P 2 P）穿透，常用于远程控制软件（TeamViewer、向日葵）、即时通讯文件传输（QQ/微信）、P 2 P 下载等场景。

### 1. 核心思想

让**内网两端的设备都主动向对方发起出站连接**，在各自的 NAT 设备上“打一个洞”，让对方的数据包能通过这个洞进来，最终实现两端直连，不需要中间服务器转发流量。

### 2. 前置辅助：STUN 协议

要打洞，两端首先得知道对方的**公网映射地址（公网 IP+公网端口）**，但内网设备自己不知道 NAT 把自己映射成了什么公网地址，这就需要**STUN 服务器**（会话穿透实用工具）来帮忙。

STUN 服务器的作用很简单：

- 内网设备主动给 STUN 服务器发一个数据包；
- STUN 服务器收到后，把数据包里的源地址（也就是 NAT 映射后的公网 IP+端口）返回给内网设备；
- 这样内网设备就知道了自己在公网上的映射地址。

### 3. 完整打洞流程（以两端都是端口限制锥形 NAT 为例）

假设有 A、B 两个内网设备，都在各自的 NAT 后面，想要直接通信：

#### 步骤 1：获取各自公网映射地址

A 和 B 分别主动向 STUN 服务器发送请求，获取到自己的公网映射地址：

- A 得到自己的公网地址：`IP_A:PORT_A`
- B 得到自己的公网地址：`IP_B:PORT_B`

#### 步骤 2：交换地址信息

A 和 B 通过一个第三方的「信令服务器」，互相交换对方的公网映射地址（信令服务器只负责传消息，不转发数据流量）。

#### 步骤 3：同时发起打洞包

A 和 B**同时向对方的公网地址发送一个 UDP 数据包**（出站连接）：

- A 发送数据包到 `IP_B:PORT_B`，这个包会到达 B 的 NAT 设备；
- B 发送数据包到 `IP_A:PORT_A`，这个包会到达 A 的 NAT 设备。

#### 步骤 4：打洞成功

- 对于 A 的 NAT 来说：A 主动给 `IP_B:PORT_B` 发了包，所以 NAT 会放行来自 `IP_B:PORT_B` 的入站包；
- 对于 B 的 NAT 来说：B 主动给 `IP_A:PORT_A` 发了包，所以 NAT 会放行来自 `IP_A:PORT_A` 的入站包；

此时，两边的 NAT 都已经“放行”了对方的地址，隧道就打通了，A 和 B 可以直接通过公网映射地址互相通信，不需要任何中转。

### 4. 打洞成功率与 NAT 类型的关系

NAT 打洞并不是 100%成功，成功率完全取决于两端的 NAT 类型：

- 锥型 NAT ↔ 锥型 NAT：几乎 100%成功；
- 锥型 NAT ↔ 对称型 NAT：有概率成功，需要端口预测；
- 对称型 NAT ↔ 对称型 NAT：几乎无法打洞成功，因为每次访问不同地址，公网端口都会变，对方无法预测。

这也是为什么远程控制软件有时候速度快（直连成功），有时候速度慢（打洞失败，走中转）。

### 5. 打洞失败的降级方案

如果 P 2 P 打洞失败，系统会自动降级为**中转服务器转发模式**，和前面讲的中转隧道原理一样，保证可用性，只是流量会经过服务器，速度取决于服务器带宽。

## 四、易混淆概念辨析

### 1. 内网穿透 vs 路由器端口映射（DMZ）

很多人会把路由器的「端口映射/虚拟服务器/DMZ」和内网穿透混淆，二者本质完全不同：

|对比项|路由器端口映射|内网穿透（中转模式）|
|---|---|---|
|核心逻辑|在路由器 NAT 表手动加固定映射，让入站连接直接转发到内网设备|内网主动出站建隧道，通过公网服务器中转流量|
|前提条件|路由器必须有**真正的公网 IP**|只要能上网就行，有无公网 IP 都可以|
|CGNAT 环境|完全无效，外层运营商 NAT 依然拦截|正常使用，不受影响|
|配置位置|需要登录路由器后台配置|只需要在内网设备装客户端|
|网络环境|只能在自己可控的路由器下使用|任何网络（校园网、公司网、4 G/5 G）都能用|

简单说：**有公网 IP，用端口映射；没有公网 IP，用内网穿透**。

### 2. 有公网 IP 还需要内网穿透吗？

如果有固定公网 IP，端口映射就能满足需求，不需要内网穿透；但如果是动态公网 IP（每次重启路由器 IP 就变），可以配合 DDNS（动态域名解析）使用，也比内网穿透速度更快、延迟更低。

## 总结

- 内网穿透的核心目标：突破 NAT 的入站拦截，让外网能访问内网服务；
- 中转隧道模式：通用性最强，靠公网服务器中转，100%成功，适合部署长期服务；
- P 2 P 打洞模式：无中转、速度快，但成功率受 NAT 类型限制，适合临时传输、远程控制。

## 一、双层 NAT 的完整拓扑结构

正常情况下，家庭网络的数据流会经过**两层 NAT 转换**，从内到外依次是：

```
内网设备（192.168.1.x）
    ↓ 第一层NAT：家庭路由器
路由器WAN口IP（运营商内网IP，如100.xx.xx.xx）
    ↓ 第二层NAT：运营商城域网CGNAT设备
运营商公网出口IP（百度/ip138查到的IP）
    ↓
公网互联网
```

其中关键区别：

- **家庭路由器 NAT**：你自己可控，可以登录后台配置端口映射、DMZ；
- **运营商 CGNAT**：部署在运营商机房，你完全没有权限配置和修改。

你在百度、ip 138 等网站查到的“外网 IP”，本质上是**运营商 CGNAT 设备的公网出口 IP**，是几十甚至上百户家庭共享的同一个 IP，并不是你家路由器独有的。

## 二、为什么端口映射穿透不了 CGNAT？

端口映射的作用，只是在**你家路由器的 NAT 映射表**里手动添加一条规则：“把公网侧 XX 端口的数据包，转发给内网 XX 设备的 XX 端口”。

但外网访问的数据包，是先到达运营商的 CGNAT 设备，再到你家路由器：

1. 外网用户向“你查到的公网 IP”发起连接请求；
2. 请求到达运营商 CGNAT 设备，CGNAT 查询自己的 NAT 映射表；
3. 因为你无权配置运营商的设备，CGNAT 表里**没有对应端口的映射记录**，不知道该把这个包转发给哪个小区、哪个用户；
4. CGNAT 直接丢弃这个数据包，连接请求根本到不了你家的路由器。

简单说：**端口映射只能解决你家路由器这一层 NAT，解决不了运营商那一层 NAT**。外层的门没打开，你只开内层的门，外面的人还是进不来。

## 三、如何自查你家是不是 CGNAT 环境？

两种最简单的判断方法：

### 方法 1：对比 WAN 口 IP 和公网 IP

1. 登录路由器管理后台，在「WAN 口设置」「上网设置」里查看当前获取到的 WAN 口 IP；
2. 打开百度搜索“IP”，记下页面显示的公网 IP；
3. 如果两个 IP**不一致**，几乎可以确定就是 CGNAT 大内网。

### 方法 2：看 WAN 口 IP 网段

IANA 专门为运营商 CGNAT 预留了私有地址段：**100.64.0.0/10**，也就是 IP 范围在 `100.64.0.0 ~ 100.127.255.255` 之间。 如果你家路由器 WAN 口 IP 落在这个区间，100%是 CGNAT 环境。

## 四、运营商为什么要部署 CGNAT？

核心原因是**IPv 4 地址枯竭**：全球 IPv 4 地址总量只有约 43 亿个，中国宽带用户基数庞大，公网 IPv 4 地址严重不足。 通过 CGNAT 让几十上百户家庭共享一个公网 IP，可以大幅节省公网 IP 资源，是运营商在 IPv 6 全面普及前的过渡方案。

## 五、CGNAT 环境下的可行解决方案

按照体验从优到劣排序：

### 1. 申请公网 IPv 4（最优方案）

拨打运营商客服电话（电信 10000、移动 10086、联通 10010），说明需求（比如“家里安装远程监控、NAS 需要远程访问”），多数地区可以免费切换为**动态公网 IP**。

- 优势：延迟最低、速度最快，配合 DDNS（动态域名解析）即可稳定使用；
- 注意：是动态公网 IP（重启路由器 IP 会变），不是固定公网 IP（固定 IP 一般是企业专线，价格很高）。

### 2. 使用 IPv 6（免费且无 NAT）

目前三大运营商基本都已为家庭宽带分配**公网 IPv 6 地址**，IPv 6 地址数量极其充足，不存在 NAT 和地址枯竭问题。 只要路由器和终端设备支持 IPv 6，就可以直接通过 IPv 6 地址从外网访问内网设备，不需要端口映射，也不需要内网穿透。

### 3. 中转式内网穿透（通用性最强）

就是 frp、ngrok、cpolar、花生壳这类工具，原理是内网主动出站建隧道，通过公网服务器中转流量。 它完全不受 CGNAT 影响——因为所有连接都是内网主动发起的出站连接，两层 NAT 都会放行，只要能上网就能用。

### 4. P 2 P 打洞类工具（适合临时远程）

比如 TeamViewer、向日葵远程控制、ToDesk 等，会优先尝试 P 2 P 打洞直连，打洞失败自动降级为服务器中转。 这类工具适合临时远程桌面、文件传输，但运营商 CGNAT 多为对称型 NAT，P 2 P 打洞成功率很低，多数时候还是走中转。  



# 聊天应用的实现原理  

这是一个非常经典的问题，刚好能把前面讲的 NAT 规则彻底落地。答案的核心是： **微信这类即时通讯软件，两个内网设备之间从来就不是「直接互相发送消息」，而是全程通过腾讯的公网服务器中转。它完美利用了 NAT「放行出站连接及该连接上的双向流量」的规则，完全绕开了入站连接的限制。**

## 一、先纠正一个直觉误区：聊天不是两人直连

几乎所有主流聊天软件（微信、QQ、钉钉、WhatsApp），默认的文字消息都采用**客户端-服务器（C/S）中转架构**，而非点对点（P 2 P）直连。

你可以这么理解：

- 你和朋友的手机，都相当于两个住在不同小区里的住户，小区大门（NAT）只许出不许进；
- 腾讯服务器相当于市中心的一个公共邮局，所有人都能主动去邮局寄信、取信；
- 你给朋友发消息，不是你直接跑到他家敲门送进去，而是你把信送到邮局，邮局再转手交给你的朋友。

全程两个人都没有主动找对方，都只是主动和公网的邮局通信，自然就不存在“入站连接被 NAT 拦截”的问题。

## 二、核心原理：利用出站长连接，实现服务器反向推送

### 1. 第一步：内网客户端主动建立长连接

手机上的微信启动后，会**主动向腾讯的公网消息服务器发起 TCP 连接**，并一直保持这条连接不断开（这就是「长连接」）。

这条连接是**内网主动发起的出站连接**，完全符合 NAT 的放行规则：

- 你的路由器 NAT 设备会生成一条映射记录：`内网手机IP:端口 ↔ 公网IP:端口 ↔ 腾讯服务器IP:端口`；
- 只要这条连接保持活跃，NAT 就会允许腾讯服务器从这条连接上往回发数据；
- 微信会定期发很小的「心跳包」给服务器，告诉 NAT“这条连接还在用”，防止因为超时被 NAT 删掉映射。

### 2. 第二步：消息全程服务器中转

当 A 给 B 发一条文字消息时，完整流程是：

1. A 的微信客户端，通过**自己已经建立好的出站长连接**，把消息发给腾讯服务器；
2. 腾讯服务器收到消息，查找到 B 当前在线的长连接通道；
3. 腾讯服务器通过**B 主动建立的那条长连接**，把消息推送给 B 的手机；
4. B 的微信收到消息，弹出通知、显示在聊天界面。

整个过程中：

- 没有任何一方主动向对方发起连接；
- 所有“入站”到手机的数据，都来自一条**已经由内网主动发起的、NAT 认可的出站连接**；
- NAT 设备只会觉得“这是内网设备连出去的连接，对方在正常回数据”，完全不会拦截。

## 三、进阶：语音视频、大文件传输会尝试 P 2 P 打洞

文字消息数据量小，全程服务器中转成本低、稳定可靠。但语音视频通话、大文件传输如果全程中转，会给服务器带来巨大的带宽压力，延迟也会更高。

这时微信就会尝试用我们之前讲过的**NAT 打洞（P 2 P 直连）**技术，能直连就直连，直连失败再退回中转：

1. **交换地址**：双方先通过腾讯服务器，借助 STUN 协议获取到各自的公网映射地址（公网 IP+端口）；
2. **尝试打洞**：双方同时向对方的公网地址发送数据包，在各自的 NAT 设备上“打洞”；
3. **成功则直连**：打洞成功后，音视频数据直接在两个设备之间传输，不经过服务器，速度快、延迟低；
4. **失败则中转**：如果遇到多层 CGNAT、对称型 NAT 等打洞困难的环境，系统会自动降级，走腾讯服务器中转，保证通话能接通。

这也是为什么有时候微信视频通话画质好、延迟低，有时候又卡的原因——成功打洞就是直连质量，打洞失败就是中转质量。

## 四、和内网穿透的本质共通

讲到这里你应该能发现，微信聊天、内网穿透、NAT 打洞，底层逻辑其实完全一致：

> **NAT 只拦截「外网主动发起的新连接」，从不拦截「内网主动发起的连接上的双向流量」。**

所有能在 NAT 环境下正常工作的网络应用，本质上都是遵守了这个规则：

- 内网穿透：内网客户端主动连公网服务器，外网请求通过服务器转进内网；
- 微信聊天：两个内网客户端都主动连公网服务器，消息通过服务器互转；
- P 2 P 文件传输：两边都主动向对方发包，把“入站”变成“出站的回应”。

永远不做被动等待入站的那一方，这就是所有内网通信的核心秘诀。  







# 大内网  
不是，这是很多人最容易混淆的一个点：**从运营商那里拿到的 IP，不等于就是公网 IP**。

100.64.x.x 这个网段，本质上是**运营商自己的大内网地址**，和你家路由器给手机分配的 192.168.x.x 性质完全一样，都属于「私有 IP」，只是规模更大、层级更高而已。

## 一、先明确：什么才算真正的公网 IP？

公网 IP（也叫全局 IP）的核心判定标准只有一个：**它能在全球互联网的骨干路由器上被直接路由，全球唯一，外网设备可以直接通过这个 IP 找到对应的设备**。

反过来，私有 IP 的特征是：

- 只能在一个局部内网内使用，出了这个内网就不生效；
- 全球公网的路由器不会转发目标地址是私有 IP 的数据包；
- 不同内网里可以重复使用同一个私有 IP，不冲突。

我们熟知的 192.168.x.x、10.x.x.x、172.16-31.x.x 是家庭/企业级私有网段； 而 **100.64.0.0/10（100.64.0.0 ~ 100.127.255.255）** 是 IANA 专门给运营商预留的**运营商级私有网段**，专门用来做 CGNAT 大内网，它同样属于私有 IP，不是公网 IP。

## 二、用一个类比彻底搞懂层级关系

你可以把整个网络想象成「快递送货」的体系：

- **真正的公网 IP** = 国家官方认证的街道门牌号（比如「XX 路 XX 号」），全国唯一，快递员可以直接送到门口。
- **运营商 CGNAT 设备** = 小区大门，它有一个正式的街道门牌号（公网 IP），所有寄给小区住户的快递，都先送到这里。
- **100.64.x.x（路由器 WAN 口 IP）** = 小区内部的楼栋号（比如「3 栋 2 单元」），只在小区内部有效，出了小区大门，这个号就没用了，快递员不可能凭这个号找到你家。
- **192.168.x.x（你家设备 IP）** = 你家里的房间号（比如「主卧」），只在你家里有效。

你家路由器的 WAN 口拿到 100.64.x.x，本质上就相当于：

> 运营商的大内网是一个超大的“小区”，你家路由器是这个小区里的一户人家，100.64.x.x 就是你在这个小区里的“内部门牌号”。

它只在运营商这个大内网里能被找到，一旦出了运营商的网络，到了公网上，这个地址是不被识别、无法路由的。

## 三、最直观的验证方法

如果你的 WAN 口 IP 真的是公网 IP，那你在百度搜索“IP”查到的地址，和路由器 WAN 口显示的地址，**必须完全一模一样**。

而 CGNAT 环境下：

- 路由器 WAN 口显示：100.64.xx.xx（运营商内网地址）
- 百度查到的公网 IP：120.xx.xx.xx / 183.xx.xx.xx（CGNAT 设备的公网出口地址）

两个地址不一样，就说明你的 WAN 口 IP 根本不是公网——外网看到的是小区大门的地址，不是你家的内部楼栋号。

## 四、为什么运营商要这么做？

核心还是 IPv 4 地址不够用。 如果每户都给一个真正的公网 IP，一个城市几百万户家庭就需要几百万个公网 IP，运营商根本没有这么多地址资源。 于是运营商就建了一个超大的“内网小区”（CGNAT），给每户分配一个内部的 100.64.x.x 地址，整个小区共用一个或几个公网 IP 对外上网，这样就能节省大量公网 IP 资源。

## 总结

- 192.168.x.x：你家的内网地址，路由器管理；
- 100.64.x.x：运营商的内网地址，CGNAT 设备管理；
- 真正的公网 IP：运营商 CGNAT 设备的出口地址，全球可路由。

你家路由器的 WAN 口，只是拿到了运营商内网里的一个“内部编号”，并不是公网 IP。
