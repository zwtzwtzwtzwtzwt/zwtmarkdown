当广播 IP 报文需要**跨路由器转发到其他子网**时，在到达目标子网之前的整条转发路径上，它都封装在**单播帧**中传输。

### 核心原理

子网定向广播（如 `10.0.0.255`）只在**目标子网内部**才有 “广播” 的语义；在跨网段的传输路径中，路由器会把它当成一个普通的单播目的地址来转发，二层目的 MAC 始终是下一跳设备的单播 MAC。

### 完整转发示例

主机 A（`192.168.1.10/24`）向 `10.0.0.255`（`10.0.0.0/24` 的子网广播地址）发送报文：

1. **主机 A 发出时**：目的 IP 是广播 IP，但二层目的 MAC 是本地网关 `192.168.1.1` 的单播 MAC，是**单播帧**。
2. **中间路由器转发时**：每一跳都根据路由表找下一跳，二层封装下一跳的单播 MAC，全程都是**单播帧**。
3. **到达目标子网网关（`10.0.0.1`）时**：
    - 若网关开启了**子网定向广播转发**：才会将报文重新封装为二层广播帧，发送到目标子网。
    - 若网关关闭该功能（现代设备默认关闭，防范 Smurf 攻击）：报文会被直接丢弃。




- #### 两种广播 IP 的具体表现
- 
- 1. **受限广播（255.255.255.255）** 只能在本地网段传播，路由器不会转发。主机发送时无需 ARP 解析，直接封装全 F 广播 MAC，是最典型的广播帧。 例：DHCP 客户端首次发现服务器的报文。
- 2. **本网段定向广播（如`192.168.1.255/24`）** 主机通过子网掩码判断，目标广播 IP 与自身属于同一网段，同样直接封装全 F 广播 MAC，在本地网段泛洪。
