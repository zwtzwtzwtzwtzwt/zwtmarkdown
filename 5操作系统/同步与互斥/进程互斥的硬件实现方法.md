在 408 计算机统考的操作系统大纲中，纯软件实现往往作为探究原理的基础概念考察，而**硬件实现方法**则是为了解决软件实现中“检查和修改”分步执行导致的不一致问题。

纯软件实现的致命弱点在于：代码执行是可以被中断的。硬件实现的核心思想就是**将“检查状态”和“修改状态”这两个操作绑定在一起，变成一个不可分割的“原子操作”（Atomic Operation）**。

常见的硬件实现方法有三种：

## 1. 中断屏蔽方法（关中断）

这是最简单、最暴力的硬件方法。既然并发是由中断引发的进程切换导致的，那我在进入临界区前，直接把中断关掉，不让 CPU 响应任何切换请求就可以了。

- **执行逻辑：**
    
    Plaintext
    
    ```
    关中断 (Disable Interrupts)
    临界区 (Critical Section)
    开中断 (Enable Interrupts)
    ```
    
- **优点：** 简单、高效。
    
- **缺点（非常明显）：**
    
    1. **不适用于多处理机（SMP）环境：** 关中断指令只能关闭当前 CPU 核心的中断，其他 CPU 核心依然可以调度其他进程来访问临界资源。
        
    2. **危险性极高：** 关中断是非常底层的特权指令。如果把这种特权交给用户态的普通进程，一旦进程在临界区内死循环，系统将直接崩溃。因此，这种方法**只适用于操作系统内核进程**，不能用于用户进程。
        

## 2. Test-and-Set 指令（TS 指令 / TSL 指令）

TS 指令（有时也称 TSL，Test-and-Set Lock）是由**硬件直接提供的一条机器指令**。虽然我们在讲解时用 C 语言伪代码来描述它，但在物理层面上，它是一个不可中断的单步机器操作。

- **硬件逻辑伪代码：**
    
    C
    
    ```
    // 这个函数的整个执行过程由硬件保证不可中断
    bool TestAndSet(bool *lock) {
        bool old = *lock;  // 记录旧值（检查）
        *lock = true;      // 无论旧值是什么，直接设为 true（上锁）
        return old;        // 返回旧值
    }
    ```
    
- **进程互斥的实现：**
    
    C
    
    ```
    bool lock = false; // 初始状态，锁是打开的
    
    // 进程代码
    while (TestAndSet(&lock)); // 如果返回 true，说明锁已经被别人拿了，继续 while 循环死等；如果返回 false，说明锁原本是开的，现在已被我原子性地锁上，退出循环进入临界区。
    // 临界区
    lock = false; // 解锁
    // 剩余区
    ```
    
- **优点：** 实现简单，适用于多物理机环境（硬件总线会保证指令的原子性）。
    
- **缺点：** 依然不满足“让权等待”。进不去的进程会卡在 `while` 循环里疯狂消耗 CPU（这种锁在现代操作系统中被称为**自旋锁 Spinlock**）。
    

## 3. Swap 指令（XCHG / Exchange 指令）

Swap 指令的作用是交换两个内存单元（或寄存器与内存）的值。与 TS 指令一样，这个交换过程是由硬件总线直接支持的**原子操作**。

- **硬件逻辑伪代码：**
    
    C
    
    ```
    // 这个函数的整个执行过程由硬件保证不可中断
    void Swap(bool *a, bool *b) {
        bool temp = *a;
        *a = *b;
        *b = temp;
    }
    ```
    
- **进程互斥的实现：**
    
    C
    
    ```
    bool lock = false; // 共享变量，表示临界区是否被锁
    
    // 进程代码
    bool key = true; // 每个进程自己的局部变量，初始想拿锁
    while (key == true) {
        Swap(&lock, &key); // 把自己手里的 true 和共享的 lock 进行交换
    }
    // 退出循环说明交换后 key 变成了 false，也就是成功拿到了一把解锁状态的 lock
    // 临界区
    lock = false; // 解锁
    // 剩余区
    ```
    
- **优点：** 逻辑与 TS 指令几乎等价，同样适用于多处理器，支持多个共享变量的并发管理。
    
- **缺点：** 同样卡在 `while` 循环中，**不满足“让权等待”**。
    

## 硬件实现与软件实现的对比总结

为了清晰掌握这些机制的优劣，可以将硬件方法与核心评价准则对应起来：

|**实现机制**|**核心原理**|**适用场景**|**最大的缺陷**|**是否满足“让权等待”？**|
|---|---|---|---|---|
|**中断屏蔽**|限制系统调度，从根源掐断并发|单核 CPU 的内核程序|无法防备多核 CPU 并发；不能交给普通用户态程序使用|不涉及（直接剥夺了切换能力）|
|**TS/TSL 指令**|硬件指令保证“读-写”一步完成|多核 CPU 环境均可|容易发生“饥饿”（有的进程运气差一直抢不到）|❌ 否，依然是忙等待（自旋）|
|**Swap 指令**|硬件指令保证“数值交换”一步完成|多核 CPU 环境均可|容易发生“饥饿”|❌ 否，依然是忙等待（自旋）|

无论是软件的 Peterson 算法，还是硬件的 TS/Swap 指令，它们都倒在了“让权等待”**这一步。要彻底解决这个耗费 CPU 空转的问题，操作系统必须亲自下场，提供包含“阻塞/唤醒”机制的高级抽象，这就是**信号量（Semaphore）**和**互斥量（Mutex）登场的原因。
