在操作系统的经典理论中，纯靠软件代码来实现进程互斥是一个不断试错和演进的过程。理解这个演进过程，核心在于掌握四个评价互斥机制的黄金准则：

1. **空闲让进**：临界区空闲时，应允许一个请求进入的进程立即进入。
    
2. **忙则等待**：已有进程在临界区时，其他试图进入的进程必须等待。
    
3. **有限等待**：等待进入的进程应该在有限时间内进入，不能引发“饥饿”。
    
4. **让权等待**：进程如果进不了临界区，应该释放 CPU，不能进入“忙等（死循环）”状态。
    

以下是软件实现互斥的四个经典算法演进，它们就像是寻找完美解决方案的四个版本：

## 1. 算法 v 1.0：单标志法（严格轮换）

这个算法的核心思想是设立一个公共的标志位 `turn`，用来指示**当前允许哪个进程进入**。

C

```
int turn = 0; // turn 表示当前允许进入临界区的进程号

// 进程 P0 的代码                 // 进程 P1 的代码
while(turn != 0);               while(turn != 1); 
// 进入临界区                     // 进入临界区
turn = 1;                       turn = 0;
// 剩余区                         // 剩余区
```

- **设计思路**：严格的交替执行（P 0 进完必须 P 1 进，P 1 进完 P 0 才能再进）。
    
- **致命缺陷**：**违反“空闲让进”**。如果 `turn = 0`，但 P 0 此时迟迟不进入临界区临界区，而 P 1 疯狂想进，P 1 也会被永远挡在外面。资源明明空闲，却因为“必须轮流来”的死板规定而浪费。
    

## 2. 算法 v 2.0：双标志先检查法

为了解决单标志法“必须交替”的死板，设计者给每个进程发了一块牌子，用数组 `flag[]` 表示**各个进程是否想要进入临界区**。

C

```
bool flag[2] = {false, false}; 

// 进程 P0                         // 进程 P1
while(flag[1]); // 1. 先检查P1想不想进   while(flag[0]); // 1. 先检查P0想不想进
flag[0] = true; // 2. 自己标记想进       flag[1] = true; // 2. 自己标记想进
// 进入临界区                        // 进入临界区
flag[0] = false;// 3. 退出，标记不想进   flag[1] = false;// 3. 退出，标记不想进
```

- **设计思路**：想进之前先看看对方的意向，对方不想进，我再进。
    
- **致命缺陷**：**违反“忙则等待”**。并发环境下，操作不是原子的。如果 P 0 刚刚执行完第 1 步（发现 P 1 不想进），还没来得及执行第 2 步时，发生了进程切换；P 1 也执行第 1 步，发现 P 0 也不想进。结果就是两人同时把 `flag` 改为 `true`，**同时冲进了临界区**，互斥失败。
    

## 3. 算法 v 3.0：双标志后检查法

既然先检查会因为时间差导致两人同时冲进去，那就把顺序反过来：**先表达自己想进的意愿，再去检查对方。**

C

```
bool flag[2] = {false, false};

// 进程 P0                         // 进程 P1
flag[0] = true; // 1. 先标记自己想进     flag[1] = true; // 1. 先标记自己想进
while(flag[1]); // 2. 后检查P1想不想进   while(flag[0]); // 2. 后检查P0想不想进
// 进入临界区                        // 进入临界区
flag[0] = false;// 3. 退出，标记不想进   flag[1] = false;// 3. 退出，标记不想进
```

- **设计思路**：先占位，再观察。
    
- **致命缺陷**：**引发“死锁”，违反“空闲让进”和“有限等待”**。如果并发执行时，P 0 和 P 1 同时执行了第 1 步（都把自己的 `flag` 设为 `true`），那么在第 2 步检查时，两人都会发现对方想进。结果就是两人互相死等（死锁），谁也进不去临界区。
    

## 4. 算法 v 4.0：Peterson 算法（完美整合版）

Peterson 算法巧妙地结合了单标志法（`turn`）和双标志法（`flag`）。它的核心逻辑非常像中国古代的“孔融让梨”：**我表达了我想进的意愿，但我非常有礼貌地让你先走。**

C

```
bool flag[2] = {false, false}; // 意愿标志
int turn = 0;                  // 谦让标志

// 进程 P0
flag[0] = true;                // 1. 表达意愿：我想进
turn = 1;                      // 2. 谦让动作：但是 P1 你优先
while(flag[1] && turn == 1);   // 3. 检查：如果 P1 想进，且真的是轮到 P1，我就等
// 进入临界区
flag[0] = false;               // 4. 退出，我不想进了

// --------------------------------------------------
// 进程 P1
flag[1] = true;                // 1. 表达意愿：我想进
turn = 0;                      // 2. 谦让动作：但是 P0 你优先
while(flag[0] && turn == 0);   // 3. 检查：如果 P0 想进，且真的是轮到 P0，我就等
// 进入临界区
flag[1] = false;               // 4. 退出，我不想进了
```

- **设计思路**：哪怕双方同时想进（`flag` 都是 `true`），因为 `turn` 变量是同一个物理内存，最后一次赋值会覆盖前一次。谁后执行“谦让（`turn = 对方`）”的操作，谁就真的会在 `while` 循环里等，完美打破了双标志后检查法中的死锁僵局。
    
- **评价**：Peterson 算法成功解决了前三个准则，做到了“空闲让进、忙则等待、有限等待”。
    

> **一个残酷的现实（最终的缺陷）**
> 
> 尽管 Peterson 算法在逻辑上近乎完美，但以上所有纯软件实现的算法，**统统都违反了第四条准则：“让权等待”**。

只要进程进不去临界区，它们都会卡在 `while(...)` 循环里空转（这被称为**忙等待**或**自旋**）。CPU 在这段时间里就在疯狂执行无意义的判断，浪费了宝贵的算力。这就是为什么后来操作系统底层必须引入**硬件指令（如 Test-and-Set、Swap）**，以及操作系统层面的信号量（Semaphore，其内部有阻塞队列实现让权等待）**和**互斥锁（Mutex）的原因。
