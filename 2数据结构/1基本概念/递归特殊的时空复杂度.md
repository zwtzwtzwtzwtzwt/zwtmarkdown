对于你给出的这段递归计算阶乘的代码：

C

```
int fact(int n) {
    if (n <= 1) return 1;          // 递归基准条件
    return n * fact(n - 1);        // 递归调用
}
```

**结论是：在这一特定算法中，它的时间复杂度和空间复杂度在“增长趋势”上是一样的，都是 $O(n)$。**

但需要明确的是，它们的**定义内涵**完全不同，以下是详细的深度对比：

### 1. 时间复杂度：$O(n)$

- **分析依据：** 我们计算的是**操作的总次数**。
    
- **推导：** 该函数从 `fact(n)` 一直递归调用到 `fact(1)`，中间总共经历了 $n-1$ 次函数调用。每一次调用内部，执行了常数次的操作（一次判断、一次乘法、一次返回，即 $O(1)$）。
    
- **计算：** $T(n) = n \times O(1) = O(n)$。
    

### 2. 空间复杂度：$O(n)$

- **分析依据：** 我们计算的是**内存栈空间的占用量**。
    
- **推导：** 递归算法的空间消耗主要来自**系统调用栈（Call Stack）**。
    
    - 当 `fact(n)` 被调用时，系统会在栈中为当前函数分配一个“栈帧”（包含参数 $n$、返回地址等）。
        
    - 在 `fact(n)` 返回之前，它必须等待 `fact(n-1)` 执行完毕。
        
    - 因此，当程序运行到最深处（`n=1`）时，内存中会同时存在 $n$ 个未执行完毕的 `fact` 函数的栈帧。
        
- **计算：** 最大递归深度为 $n$，每个栈帧占用常数空间 $O(1)$，总空间复杂度 $S(n) = n \times O(1) = O(n)$。
    

### **为什么它们在“数值”上一样，但在“分析逻辑”上完全不同？**

虽然结果都是 $O(n)$，但你在分析题目时，**大脑中的思维回路应该是两条线**：

1. **看时间时：** 问自己“这个基本操作 `*` 一共被执行了多少次？”（这是在数**时间轴**上的点）。
    
2. **看空间时：** 问自己“在最深的那一瞬间，有多少个函数堆在内存里没干完活？”（这是在看**空间轴**上的宽度）。
    

### **重要提示：什么时候它们会不一样？**

理解这一点能帮你通过所有相关的算法题。并不是所有递归算法的时间和空间复杂度都是一样的，例如：

- **斐波那契数列的简单递归：**
    
    C
    
    ```
    int fib(int n) {
        if (n <= 2) return 1;
        return fib(n-1) + fib(n-2);
    }
    ```
    
    - **时间复杂度：$O(2^n)$ ** （因为产生了一个巨大的递归树）。
        
    - **空间复杂度：$O(n)$ ** （因为递归树的最大高度只有 $n$）。
        

**总结：** 在你给出的阶乘代码中，因为它是线性的递归调用链，所以时间和空间巧合地都是 $O(n)$。但在更复杂的递归算法中，时间复杂度往往远高于空间复杂度。
