分析算法的空间复杂度，核心目的是**评估随着问题规模 $n$ 的增大，算法执行所需要的额外存储空间的增长趋势**。

空间复杂度通常记作 $S(n) = O(f(n))$。分析它时，我们通常不考虑程序代码本身或原始输入数据所占用的空间，而是重点关注**辅助空间**（算法运行过程中额外分配的空间）。

以下是分析空间复杂度的核心步骤和常见场景：

### **1. 拆解内存占用的三个部分**

在分析时，算法占用的内存可以粗略分为三块，我们需要精准定位哪一块在随规模 $n$ 变化：

- **指令空间：** 存放编译后程序代码的空间。这部分是固定的，与输入规模 $n$ 无关，**忽略不计**。
    
- **数据空间：** 存放原始输入数据本身的空间。大部分统考或机试题目中，这部分算作“既定事实”，**通常忽略不计**（除非题目特别强调原地操作 In-place）。
    
- **辅助空间（核心考点）：** 算法为了完成计算，额外声明的变量、数组、哈希表，以及递归调用时使用的系统栈空间。**空间复杂度主要就是分析这一部分。**
    

### **2. 分析空间复杂度的标准步骤**

1. **确定问题规模 $n$：** 明确输入数据中哪个指标代表了数据的体量（例如数组的长度、树的节点数、矩阵的阶数等）。
    
2. **寻找额外分配的数据结构：** 检查代码中是否有 `new`、`malloc` 或者动态容器初始化操作。观察这些数据结构的尺寸是否依赖于 $n$。
    
3. **检查是否包含递归：** 如果有递归，必须画出递归树，计算**递归的最大深度**。每一次递归调用都需要在内存栈中保存上下文，因此递归深度直接决定了栈空间的消耗。
    
4. **合并与化简：** 将所有辅助空间相加，提取最高阶项并去掉常数系数，得出最终的大 $O$ 记号。
    

### **3. 常见空间复杂度图解与实例**

|**复杂度级别**|**典型数据结构或场景**|**代码特征示例**|
|---|---|---|
|** $O(1)$ ** 常数阶|几个普通的局部变量、指针| `int a = 0, b = 1;` 无论 $n$ 多大，只开辟固定数量的变量。|
|** $O(n)$ ** 线性阶|一维数组、哈希表、线性递归| `int[] arr = new int[n];` 或最大深度为 $n$ 的递归。|
|** $O(n^2)$ ** 平方阶|二维数组、矩阵、邻接矩阵| `int[][] matrix = new int[n][n];` |
|** $O(\log n)$ ** 对数阶|二分查找的递归实现、快速排序|递归树的最大深度通常为 $\log_2 n$，栈空间消耗对数级。|

### **4. 重点突破：递归算法的空间复杂度**

对于非递归的普通循环算法，看定义了多大的数组基本就能确定空间复杂度。但对于递归算法，空间复杂度有一个核心公式：

> **递归空间复杂度 = 每次递归分配的空间大小 $\times$ 最大递归深度**

**案例 A：线性递归（如前面的阶乘）**

每次递归只传递常数个参数（分配 $O(1)$ 空间），但递归一直深入到 $n=1$ 才开始返回，最大深度为 $n$。

空间复杂度：$O(1) \times n = O(n)$

**案例 B：树形递归（如求斐波那契数列 `f(n) = f(n-1) + f(n-2)`）**

虽然它总共调用了指数级别的次数（时间复杂度为 $O(2^n)$），但它的**最大深度**（即同时压在栈里的未执行完的函数数量）只有 $n$ 层。

空间复杂度：$O(1) \times n = O(n)$ （这是一个极易错的考点，时间是指数级，但空间是线性级）。

**案例 C：二分法递归（如归并排序的拆分阶段）**

每次将数组一分为二，递归到底层的深度只有 $\log_2 n$ 层。

空间复杂度（仅看调用栈）：$O(\log n)$。
