在 C 语言中，数组的定义主要分为**静态定义（Static Allocation）**和**动态定义（Dynamic Allocation）**。它们在语法、内存分配区域以及生命周期上有着本质的区别。

以下是它们的详细方式和对比：

### 一、 静态定义数组 (Static Array)

静态数组是指在**编译时**就确定了大小的数组。它的内存通常分配在**栈区（Stack）**（如果是局部变量）或**全局/静态存储区**（如果是全局变量或使用了 `static` 关键字）。

#### 1. 定义方式

定义静态数组时，必须提供一个常量表达式来指定数组的大小（C 99 标准引入了变长数组 VLA，允许用变量指定大小，但它依然是在栈上分配的局部数组）。

C

```
// 方式一：指定大小，不初始化（内部数据是随机的垃圾值）
int arr1[10]; 

// 方式二：指定大小并初始化
int arr2[5] = {1, 2, 3, 4, 5}; 

// 方式三：不指定大小，由编译器根据初始化列表自动推导
int arr3[] = {10, 20, 30}; 
```

#### 2. 特点

- **大小固定：** 一旦定义，数组的长度在运行期间**不能更改**。
    
- **自动管理：** 如果是局部数组，当程序运行离开该数组所在的作用域（如函数结束）时，系统会自动释放其占用的内存。
    

### 二、 动态定义数组 (Dynamic Array)

动态数组是指在**程序运行时（Runtime）**，根据实际需要手动向系统申请内存来创建的数组。它的内存分配在**堆区（Heap）**。

#### 1. 定义方式

动态数组的创建和销毁依赖于标准库函数 `<stdlib.h>` 中的 `malloc`（或 `calloc`）和 `free`。

C

```
#include <stdio.h>
#include <stdlib.h> // 必须包含此头文件

int main() {
    int n;
    printf("请输入数组大小: ");
    scanf("%d", &n);

    // 方式：使用 malloc 动态分配内存
    // malloc 返回的是 void* 指针，需要强转为对应类型的指针
    int *arr = (int *)malloc(n * sizeof(int));

    if (arr == NULL) {
        printf("内存分配失败！\n");
        return 1;
    }

    // 使用数组
    for (int i = 0; i < n; i++) {
        arr[i] = i + 1; 
    }

    // 可以使用 realloc 动态调整数组大小
    // arr = (int *)realloc(arr, (n + 5) * sizeof(int));

    // 重点：使用完毕后，必须手动释放内存！
    free(arr);
    arr = NULL; // 释放后将指针置空，防止野指针

    return 0;
}
```

#### 2. 特点

- **大小灵活：** 可以在运行时根据用户输入或计算结果决定数组大小，甚至可以用 `realloc` 动态扩容或缩容。
    
- **手动管理：** 程序员必须对申请的内存负责。使用完毕后**必须调用 `free()` 释放内存**，否则会导致内存泄漏（Memory Leak）。
    

### 三、 核心区别对比

为了更清晰地理解，这里将它们的区别总结为一个表格：

|**特性**|**静态数组 (Static Array)**|**动态数组 (Dynamic Array)**|
|---|---|---|
|**分配时机**|编译时（Compile Time）确定大小。|运行时（Runtime）确定大小。|
|**内存位置**|**栈区** (局部变量) 或 全局/静态区。|**堆区** (Heap)。|
|**空间大小**|受限于栈空间（通常较小，仅几 MB），定义过大容易引发 **栈溢出 (Stack Overflow)**。|受限于系统的虚拟内存（通常很大），适合存储海量数据。|
|**生命周期**|**自动管理**。离开作用域自动销毁。|**手动管理**。需通过 `free()` 手动销毁，否则常驻内存。|
|**灵活性**|**极低**。长度固定，无法在运行中改变大小。|**极高**。可随时使用 `realloc()` 改变大小。|
|**访问效率**|**稍高**。直接通过内存偏移量访问。|**略低**。需要通过指针间接寻址，且申请/释放内存有函数开销。|
|**安全性**|相对安全，不容易引起内存泄漏。|需要小心处理，容易出现内存泄漏、野指针、越界访问等问题。|

**总结建议：**

如果在编写代码时，你**明确知道所需的数据量最大是多少**，且数据量不大，首选**静态定义**，因为它简单、安全、效率高。如果你处理的数据量未知（比如需要读取用户输入或者大型文件），或者数据量非常大（可能会撑爆栈内存），则必须使用**动态定义**。
