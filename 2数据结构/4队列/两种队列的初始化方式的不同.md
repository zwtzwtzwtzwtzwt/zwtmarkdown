这两种初始化方式的核心区别，在于 ** `rear` 指针的物理含义不同**。

在 408 数据结构考试中，这两种写法都非常常见，本质上只是指针的“错位”：

- **方式一（`rear = front = 0`）：** `rear` 指向队尾元素的**下一个空位置**。入队时**先赋值，后移动指针**。
    
- **方式二（`rear = maxsize - 1`）：** `rear` 指向队尾元素的**真实所在位置**。入队时**先移动指针，后赋值**。
    

为了直观对比，假设队列数组为 `data[MaxSize]`，并且**均采用“牺牲一个存储单元”的常规策略**来区分队空和队满。以下是两者的全方位对比：

### 核心公式对比速查表

|**操作**|**方式一：rear = front = 0 (rear 指向下一个空位)**|**方式二：rear = MaxSize - 1, front = 0 (rear 指向当前队尾)**|
|---|---|---|
|**入队 (Enqueue)**| `data[rear] = x;`<br><br>  <br><br>$rear = (rear + 1) \pmod{MaxSize}$ | $rear = (rear + 1) \pmod{MaxSize}$;<br><br>  <br><br>`data[rear] = x;` |
|**出队 (Dequeue)**| `x = data[front];`<br><br>  <br><br>$front = (front + 1) \pmod{MaxSize}$ | `x = data[front];`<br><br>  <br><br>$front = (front + 1) \pmod{MaxSize}$ |
|**判空 (isEmpty)**| $rear == front$ | $(rear + 1) \pmod{MaxSize} == front$ |
|**判满 (isFull)**| $(rear + 1) \pmod{MaxSize} == front$ | $(rear + 2) \pmod{MaxSize} == front$ |
|**算队长 (Length)**| $(rear - front + MaxSize) \pmod{MaxSize}$ | $(rear - front + 1 + MaxSize) \pmod{MaxSize}$ |

### 详细原理解析

#### 1. 初始化 `rear = front = 0` （王道教材最常见的默认方式）

- **逻辑起点**：队列刚建立时，`data[0]` 是空的，`front` 指向这个位置准备出队（虽然没东西），`rear` 也指向这个位置，表示下一个要插入数据的地方就是 `data[0]`。
    
- **出/入队逻辑**：
    
    - 因为 `rear` 是空位，所以新元素来了直接放进去，放完之后 `rear` 必须向后挪一步，寻找下一个空位。
        
    - 出队时，`front` 指向的就是真实的队首元素，直接取走，然后 `front` 往后挪一步。
        
- **判空与判满**：
    
    - 队空：当 `rear` 绕了一圈追上 `front`，即 $rear == front$ 时，队空。
        
    - 队满：为了不和队空条件冲突，当 `rear` 的下一个位置就是 `front` 时，认为队满，即 $(rear + 1) \pmod{MaxSize} == front$。
        

#### 2. 初始化 `rear = MaxSize - 1, front = 0` （考查指针灵活度的常考变体）

- **逻辑起点**：`rear` 被严格定义为“最后一个进去的元素所在的位置”。由于刚初始化时队列里没有元素，所以 `rear` 必须停留在 `front` 的“前一个位置”。在循环数组中，`0` 的前一个位置就是 `MaxSize - 1`。
    
- **出/入队逻辑**：
    
    - 入队时，因为 `rear` 当前指向的要么是上一个有效元素，要么是初始化的“假”队尾，所以必须**先让 `rear` 往前走一步**找到空位，然后再把数据塞进去。
        
    - 出队逻辑没有任何变化，`front` 依然指向真实的队首元素。
        
- **判空与判满**：
    
    - 队空：当 `rear` 的下一个位置是 `front`，说明 `rear` 被打回了原形（停在队首的前一个位置），即 $(rear + 1) \pmod{MaxSize} == front$。
        
    - 队满：同样需要牺牲一个单元。当 `rear` 往前走**两步**就会撞上 `front` 时，说明再插入一个元素就满了，即 $(rear + 2) \pmod{MaxSize} == front$。
        
- **算队长**：因为 `rear` 和 `front` 之间包含了真实的头尾元素，相当于闭区间 $[front, rear]$，所以在计算距离时，除了加上 $MaxSize$ 防止负数，还需要额外 $+1$ 才能算出正确的元素个数。

在循环队列中，计算队长（队列长度）的核心难点在于**队列是“循环”的**。因为指针会绕回数组的开头，所以常常会出现队尾指针的下标反而小于队首指针下标的情况（即 $rear < front$）。

为了统一处理这种“指针倒挂”的情况，推导队长公式时需要用到**取模运算（求余数）**。我们分情况来推导这两种初始化方式的队长公式：

### 核心通用思想：化“循环”为“直线”

假设我们暂时不考虑循环，只把队列当成一条直直的数组，那么：

1. 先计算常规的直线距离。
    
2. 加上 $MaxSize$（为了防止出现负数）。
    
3. 最后对 $MaxSize$ 取模（把越界的部分砍掉，拉回一个周期内）。
    

### 情况一：`rear` 指向下一个空位置（初始化 `rear = front = 0`）

在这种情况下，`rear` 代表的是“下一个数据要放进来的位置索引”，而 `front` 代表“当前第一个数据所在的位置索引”。

- **推导过程：**
    
    - 如果不考虑循环（即 $rear \ge front$），队列中的元素个数恰好就是两个指针下标相减。例如，`front = 0`，`rear = 3`，里面的元素分布在索引 0、1、2，数量正好是 $3 - 0 = 3$。所以直线长度为 $rear - front$。
        
    - 但如果出现了循环（即 $rear < front$），此时 $rear - front$ 是一个负数。为了计算正确的正数长度，我们需要把它加上整个数组的总长度 $MaxSize$。
        
    - 为了用一个通用的代数式把“$rear \ge front$”和“$rear < front$”统一起来，我们将 $(rear - front)$ 加上 $MaxSize$ 确保为正数，再整体除以 $MaxSize$ 取余数。
        
- **最终公式：**
    
    $$Length = (rear - front + MaxSize) \pmod{MaxSize}$$
    

### 情况二：`rear` 指向当前队尾元素（初始化 `rear = MaxSize - 1, front = 0`）

在这种情况下，`rear` 代表的是“最后一个放进来的数据所在的位置索引”，`front` 依然代表“当前第一个数据所在的位置索引”。

- **推导过程：**
    
    - 如果不考虑循环（即 $rear \ge front$），队列中的元素是从索引 `front` 一直连续排到索引 `rear`。这是一个闭区间 $[front, rear]$，它里面包含的元素个数应该是下标之差再加一，即 $rear - front + 1$。例如，`front = 0`，`rear = 2`，元素在 0、1、2 位置，数量是 $2 - 0 + 1 = 3$。
        
    - 同样地，为了处理 $rear < front$ 的循环情况，并且防止负数出现，我们需要给这个基础距离加上 $MaxSize$。
        
    - 最后，用取模运算将结果限制在一个周期内。
        
- **最终公式：**
    
    $$Length = (rear - front + 1 + MaxSize) \pmod{MaxSize}$$
    

总结来说，公式里加上的那个“1”，纯粹是因为第二种情况下的 `rear` 指针往前挪了一个单位，使得原本的前开后闭区间变成了闭区间。
