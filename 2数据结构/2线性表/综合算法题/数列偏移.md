别这么想，很多时候觉得绕，纯粹是因为数学公式把简单的物理过程给掩盖了。我们先把取模运算彻底抛开，用最朴素的“分块搬家”思维，结合左闭右开区间 `[0, n)` 来把这层映射关系拆解清楚。

### 1. 拆解映射关系（不用模运算）

我们要把数组循环左移 `p` 个位置，其实就像是切蛋糕：把数组从位置 `p` 切成前后两截，然后把前面那一截挪到后面去。

既然新数组 `R_new` 的下标范围是完整的左闭右开区间 `[0, n)`，我们就按顺序把它分成两段来填坑：

- **第一段：填入原本在后面的元素**
    
    - 新数组的头部，应该装原数组后半截的数据。
        
    - 新数组的下标范围是 `[0, n - p)`。
        
    - 这些位置要填入原数组从 `p` 开始的数据。
        
    - **映射规律：** 当新下标 `i` 在 `[0, n - p)` 范围内时，它对应的原数组下标就是 `i + p`。
        
- **第二段：填入原本在前面的元素**
    
    - 新数组的尾部，用来装原数组前半截的数据（也就是被左移挤到最后面的那部分）。
        
    - 新数组的下标范围是 `[n - p, n)`。
        
    - 这些位置要填入原数组从 `0` 开始的数据。
        
    - **映射规律：** 当新下标 `i` 增加到 `n - p` 及以上时，如果我们直接用 `i + p`，下标就大于等于 `n`（越界）了。所以我们要把下标拉回头部，手动减去一个数组长度 `n`。此时对应的原数组下标是 `i + p - n`。
        

### 2. C++ 代码实现

按照上面的“两段式”映射逻辑，我们完全可以用一个原汁原味的 `if-else` 来实现，逻辑极其清晰：

C++

```
void shiftLeft(int R[], int n, int p) {
    // 动态开辟一个长度为 n 的辅助数组
    int* R_new = new int[n]; 

    // 遍历新数组的左闭右开区间 [0, n)
    for (int i = 0; i < n; i++) {
        if (i < n - p) {
            // 第一段：直接加上偏移量 p
            R_new[i] = R[i + p];
        } else {
            // 第二段：加上偏移量 p 后越界，需要手动修正偏移
            R_new[i] = R[i + p - n];
        }
    }

    // 将映射好的新数组完全拷贝回原数组
    for (int i = 0; i < n; i++) {
        R[i] = R_new[i];
    }
    
    // 释放辅助数组内存
    delete[] R_new;
}
```

### 3. 代码进阶反思

你看，不用模运算我们也能把代码写得很明白。不过在实际的工程开发或高强度的编程题中，像这样**手动去写偏移修正逻辑（也就是代码里的 `i + p - n`）是非常容易写错边界条件并引发 Bug 的**。

在数组轮转这类场景下，采用模运算其实是一种更鲁棒（robust）的做法。

仔细观察代码逻辑你会发现：当 `i + p` 的值超过了 `n` 时，我们就减去 `n`。这恰恰就是取模运算 `(i + p) % n` 的底层物理意义——它能在越界时，自动且精准地帮我们完成偏移修正。

把朴素逻辑理顺之后，以后再写这类循环移位算法，直接把 `if-else` 替换成模运算，既省事又安全。
