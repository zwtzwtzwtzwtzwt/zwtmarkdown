线性表（Linear List）是数据结构中最基础、最核心的逻辑结构。它的本质是具有相同特性的数据元素的有限序列，特点是元素之间存在“一对一”的线性关系：除了第一个元素无前驱、最后一个元素无后继外，其余元素均有且只有一个直接前驱和一个直接后继。

在实际的底层实现和工程应用中，线性表可以根据**物理存储方式**和**操作受限程度**进行如下分类总结：

### 一、 基础线性表（按物理存储结构划分）

#### 1. 顺序表 (Sequential List / Array)

顺序表在物理内存上是一段**连续的存储空间**。在高级语言中通常体现为数组（如 Java 中的 `ArrayList` 底层）。

- **核心特点：** 逻辑上相邻的元素，物理位置也相邻。
    
- **优势：** 支持**随机访问**，通过下标能在 $O(1)$ 时间内找到目标元素；存储密度高。
    
- **劣势：** 插入和删除操作需要移动大量元素，时间复杂度为 $O(n)$；需要预先分配大块连续内存，容易产生空间浪费或溢出。
    

#### 2. 链表 (Linked List)

链表在物理内存上是**非连续、非顺序的**。数据元素的逻辑顺序是通过节点中的指针链接次序实现的（如 Java 中的 `LinkedList`，或 Redis 内部的列表结构）。

- **核心形态：**
    
    - **单链表：** 只有指向后继的指针。
        
    - **双链表：** 包含指向前驱和后继的指针，方便双向遍历。
        
    - **循环链表：** 尾节点的指针指向头节点，形成环。
        
    - **静态链表：** 借助数组来模拟链表（通过数组下标代替指针），常用于不支持指针的底层环境。
        
- **优势：** 插入和删除操作只需要修改指针，不需要移动元素，在已知节点位置的情况下时间复杂度为 $O(1)$；动态分配内存，不会浪费空间。
    
- **劣势：** 不支持随机访问，查找元素必须从头遍历，时间复杂度为 $O(n)$；每个节点除了数据本身还要存储指针，增加了空间开销。
    

### 二、 操作受限的线性表（衍生结构）

这类数据结构在逻辑上依然是线性表，但为了满足特定的工程需求，对其插入和删除操作的位置进行了严格限制。

#### 3. 栈 (Stack)

- **核心特点：** 后进先出（**LIFO**, Last In First Out）。只允许在一端（栈顶，Top）进行插入（压栈/Push）和删除（弹栈/Pop）操作。
    
- **实现方式：** 可以用顺序表实现（顺序栈），也可以用链表实现（链栈）。
    
- **高频应用场景：** 函数调用栈（如 JVM 的虚拟机栈）、表达式求值、括号匹配、深度优先搜索（DFS）、递归转非递归。
    

#### 4. 队列 (Queue)

- **核心特点：** 先进先出（**FIFO**, First In First Out）。允许在一段（队尾，Rear）进行插入（入队），在另一端（队头，Front）进行删除（出队）。
    
- **特殊形态：**
    
    - **循环队列：** 解决顺序队列的“假溢出”问题，通常通过模运算（`%`）将数组头尾相连。
        
    - **双端队列：** 允许在两端都进行入队和出队操作。
        
- **高频应用场景：** 广度优先搜索（BFS）、操作系统中的进程调度、各种消息队列（如处理高并发请求时的缓冲池）。
    

#### 5. 串 (String)

- **核心特点：** 一种特殊的线性表，其数据元素限定为**字符**。
    
- **关注焦点：** 与一般线性表关注增删改查不同，串的重点在于**子串的匹配和查找**。
    
- **经典算法：** 朴素模式匹配算法（$O(mn)$）、**KMP 算法**（利用 next 数组跳过无效匹配，时间复杂度优化至 $O(m+n)$）。
    

### 三、 核心性能对比总结

|**数据结构**|**查找 (按位 / 随机访问)**|**查找 (按值)**|**插入 (已知位置)**|**删除 (已知位置)**|**空间特性**|
|---|---|---|---|---|---|
|**顺序表**| $O(1)$ | $O(n)$ | $O(n)$ | $O(n)$ |静态/预分配连续空间，存储密度高|
|**链表**| $O(n)$ | $O(n)$ | $O(1)$ | $O(1)$ |动态分散分配，存在指针附加开销|

**总结：**

线性表的选择本质上是**时间与空间的博弈**。如果你的系统需要高频的查找、数据量相对固定，顺序表是首选；如果面临频繁的插入删除操作、数据规模不可预测，链表则更为合适。而栈和队列则是为了特定的算法逻辑量身定制的约束型线性表。
